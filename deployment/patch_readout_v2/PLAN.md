# patch_readout_v2 计划：让策略在陌生画面上仍然靠画面决策（方向 1）

2026-11-02 草稿，尚未写代码、尚未提交集群。不改动 patch_readout_v1 和任何旧结果。

## 1. 要解决的问题（来自 20261102 LIBERO 工程诊断）

| 证据 | 文件 |
|---|---|
| A3 过 Bridge 离线门槛（开发集首命令 0.080 vs 零命令 0.187） | reports/patch_readout_239393 |
| LIBERO 仿真 run1：一路往 +y 和上方漂移 0.24 m，夹爪始终张开 | run1/report.json |
| LIBERO 画面离 Bridge 远：DINO 最近邻余弦 0.36（Bridge 内部 0.69） | image_check_v2.json |
| 在 Bridge 画面上夹爪状态几乎不影响输出（<1 mm）；在 LIBERO 画面上"已知张开"推动 +3~+11 mm 的 +y | bridge_gripper_check.json, gripper_scene_check.json |
| 夹爪状态固定为未知（run2）：+y 减半，但继续上升 0.24 m | run2/report.json |
| 绝对位置输入在 LIBERO 超出 Bridge 范围 20σ 以上 | 上一轮对话的输入对比 |

结论：模型认不出陌生画面时，会转去依赖本体输入（夹爪状态、绝对位置），从而产生固定方向的漂移。v2 的目标是：**在不使用任何 LIBERO 数据的前提下，降低对本体输入的依赖，并让模型见过更多画面风格。**

## 2. 改动（只改 Bridge 源端训练）

| 编号 | 改动 | 理由 |
|---|---|---|
| a | 去掉绝对位姿输入 pose18 | LIBERO 下超范围 20σ，又没有校准；跨机器人本来就不可比 |
| b | 去掉夹爪状态输入 current2 和上一条命令 prev_command（后者含夹爪值） | 直接造成 ±y 漂移；在 Bridge 画面上它本来就几乎没用 |
| c | 只保留相对运动 state_delta（上一时刻位姿差），丢弃率提高到 0.5 | 相对量与绝对坐标无关；保留"速度"信息，这是 A2 过门槛的主要来源 |
| d | 缓存时为每张图预先生成 K=4 个增强版本，训练时随机取一个 | 不需要每步跑 ViT-L，仍能在缓存框架内做图像增强 |

增强 d 的内容（与目标域无关的通用增强，不看 LIBERO 画面来调参）：随机缩放裁剪（面积 0.7–1.0）、颜色抖动（亮度/对比度/饱和度 ±0.3，色相 ±0.05）、随机高斯模糊、50% 概率先降到 128×128 再放大（LIBERO 渲染分辨率是 128，但这是公开的通用低分辨率增强，不读 LIBERO 图像）。第 0 个版本保留原图，评估只用原图。

## 4. 预算（集群单 A40，Slurm 上限 3.5 小时）

- 增强缓存：10416 窗口 × 4 个版本，只存池化后的 65 个 token，约 5.5 GB；预计 15 分钟以内（v1 原图缓存用了 2.7 分钟）。
- 训练：3 个配置 × 约 17 分钟 ≈ 1 小时。
- 合计约 1.5 小时，远低于 12 小时上限。

## 5. 预先固定的判定（看结果前写定）

**第 1 关：Bridge 离线门槛**（与 v1 完全相同）。两个角色上，点预测的首命令位置和全段位置都 ≤ 0.9×零命令，并且 bootstrap 95% 上界 < 0。只看最终端点，不挑 checkpoint。

**第 2 关：LIBERO 离线检查**（本机，复用 20261102 的脚本；只读 64 个任务的初始画面，不读动作）：
1. 看画面：在 64 个 LIBERO 场景间，首航点的散布 ≥ 同模型在 Bridge 开发集上散布的 70%。
2. 不漂移：64 个场景的首航点平均向量长度 ≤ 首航点平均长度的 0.5，也就是说不能所有场景都往同一个方向走。B0 在这一项上作为对照。

**第 3 关：LIBERO 工程仿真**（本机，与 run1 同一任务、同一协议，只换策略）：单方向净漂移 < 0.10 m（run1 是 0.24 m）。成功率只记录，不作为判据：单个 episode 没有统计意义。

**之后怎么走：**
- 过了第 3 关的最佳配置，成为老师 5 条件/13 模型矩阵的"无增强"基础。矩阵的 13 次训练也用缓存方式，步数按本计划的 10000 步执行（原计划是 65536 步，这一改动要在论文里说明，并告知老师）。
- 如果第 1 关没过：说明去掉本体输入后，在 Bridge 上也学不会。这时记录为结果，再决定是否加 Fractal。
- 如果第 1 关过了、第 2 或第 3 关没过：说明问题主要在画面差距本身，记录为负结果，再讨论下一步。

## 6. 已知风险

- **坐标轴没有校准**：Bridge→LIBERO 的坐标轴对应仍然是"假设相同"。即使模型不再漂移，方向也可能是错的。本计划不处理这个问题，只在报告里注明。
- 去掉夹爪状态后，模型只能从画面判断夹爪现在是张开还是闭合，Bridge 上的夹爪准确率可能下降。这一项只报告，不设门槛。
- 单 seed 诊断，不是正式结果。
