# 207558整体训练方案审查与下一步边界

本次只读取已有清单、代码、抽样计划及报告，没有读原始数据集、图像或动作数组，没有加载模型、生成预测、训练或提交作业。207558仍是主参照，没有修改生产训练入口或旧配置。

**结论：现有有效结果是五个已见任务上的离线位姿预测基线；目前仍缺覆盖完整操作时段、联合学习夹爪并能执行的完整策略。没有找到一个已经证实能解释全部泛化误差的大bug，也没有获得新的性能提升。** 下一步应补全正式训练的数据/监督契约，先做CPU数据入口验证，再确定是否值得一轮新的GPU训练。不能把“已发现方案缺口”写成“已找到泛化根因”。

## 1. 实际训练了什么

207558使用405条训练演示、1836窗口、8192次batch8更新，开发为10条演示40窗口。五条固定指令如下。演示不是随机抽来的几段孤立图片：每条入选演示都保留了全部“从0起每隔4帧、存在完整16步真实未来”的起点。

| 指令 | 训练演示 | 训练窗口 | 所有训练抽取次数占比 | 每窗平均被抽取次数 |
|---|---:|---:|---:|---:|
| 关闭微波炉 | 64 | 342 | 25.00% | 47.91 |
| 关闭抽屉 | 93 | 491 | 18.75% | 25.03 |

| 取西兰花 | 55 | 308 | 18.75% | 39.90 |

这些任务份额刻意继承早期128窗的抽样槽，以便比较覆盖实验，并非当前1836窗口的自然频率。它是一项明确的加权选择，不是已经证实的错误；本次不改变比例或启动重采样训练。训练记录共65536次窗口抽取，不是65536条独立演示。

入选范围是既有五任务的有界分片扫描和每任务上限，不是全部Bridge、全部任务或全部已下载数据。七条候选因有效末步夹爪无法按既定反向扫描解析为二值而排除，不能为补数量静默改标签。当前405条来源归为12个目录组，目录名不能证明相机/布局一致。

## 2. “没有把每帧作为输入”具体意味着什么

对于有T张观察的演示，当前规则是`range(0, T-16, 4)`。输入在t，目标为t+1至t+16相对同一t的未来实测位姿，配t至t+15有效夹爪命令。

| 全405条训练演示的索引统计 | 数量 |
|---|---:|
| 原记录观察帧 | 13214 |
| 至少还有一个真实未来观察的当前时刻 | 12809 |
| 有完整16步真实未来的当前时刻 | 6734 |
| 当前实际用作输入的起点 | 1836 |
| 因步长4跳过、但有完整16步未来的起点 | 4898 |
| 因不足16步未来排除的后段当前时刻 | 6075，即每演示15个 |
| 已作为未来目标出现的不同观察帧（演示内去重） | 12204 |

因此1836个起点占可提供下一步监督时刻的14.33%，**不是只用了14.33%的位姿目标**。重叠16步目标已覆盖大量原记录；“当作预测答案看过某一帧的状态”和“用那一帧的画面决定下一步”是不同训练关系。

最后一张观察本身没有下一步实测标签，不在12809和6075内。不能用最后图像反复复制，声称获得了真实停位监督。后段15个时刻也不自动等于抓取、释放或保持阶段；本次只有索引统计，没有语义阶段标注。

现有开发40窗及已完成的13演示验收也采用完整未来窗口。后段输入缺失对完整闭环训练构成覆盖限制，但**不能由此推断它导致了这些完整窗口上的既有误差**。

## 3. 与原论文代码的对应，哪些还未实现

本地保存的作者PushT检查点使用horizon16、两步观察，数据设置pad_before1、pad_after7。作者的SequenceSampler逐个生成序列起点，并在边界复制记录首末值。207558则只用完整未来的步长4起点；其“历史”分支两次调用同一当前图像/指令token，没有使用两张不同时间的记录图像。

这是可核对的实现差别，不是再次猜测采样公式；调度器数值对照、归一化往返及图像身份检查已有证据，不重复。真正上一帧历史的对照204258也已失败并结束，不能把这项差异再包装成尚未尝试的修复。

作者PushT预测的是另一环境的动作序列，其动作和观察对齐与Bridge未来实测位姿不同。作者复制末动作的语义不能直接变成Bridge中不存在的未来测量；照搬padding并不等于复现成功。若增加不完整未来窗口，必须明确有效目标、填充值、加噪和网络接收的无效槽规则，以及损失掩码。现有loader中的schema维度掩码不是这一时间有效性掩码。

此外，当前405系列只优化七维位姿去噪MSE；夹爪相关参数被冻结，没有夹爪损失。原配置中“单独夹爪头存在”不等于这一检查点训练过它。旧Bridge八窗联合拟合和Panda已见场景抓取是其他权重的结果，不能拼接成207558完整策略。补齐夹爪是完整功能所需，也不能承诺它会改善位姿泛化。

## 4. 已有评价能支持多大的泛化结论

训练/开发在TFRecord记录身份和来源文件加episode_id身份上不相交。但五条指令都在训练中出现，来源目录不能证明相机或布局划分。因此当前可称“已见任务的新演示离线位姿表现”，不能称未见任务、相机或机器人泛化。

已完成208056独立验收：13演示60窗口，演示等权207558为4.766cm/12.045°，不动7.779cm/12.742°，保持原结论。旧开发10演示40窗口是另一集合，窗口等权6.808cm/15.139°，不动8.212cm/15.099°；后者旋转略差。两集合不混比。

13条验收已经看过结果，后续不能继续作为未触碰测试或选模依据。正式新训练应先固定内部验证及最终新演示集合；新窗口必须按整条演示隔离，不能从已训练轨迹抽几帧冒充独立泛化。若没有相机/布局证据，就明确只做演示留出。

## 6. 建议下一步及停止边界

**下一项交付：完整演示训练入口的数据与损失契约，加CPU验证报告；不是先提交另一轮GPU预检。**

先固定207558的405条演示、五任务、步长4、单位/参考系、原模型结构及旧1836窗。设计后段起点的可变真实未来长度，保留全部旧窗；若仅扩展到仍有下一帧的步长4起点，元数据推算总3394窗，新增1558个后段起点。3394是待验证的数据入口规模，不是已经生成、编码或训练的样本，也不等于使用每一帧。

CPU契约必须回答：每槽是否有真实未来；位姿与夹爪如何对齐；无效未来如何填充并参与加噪；卷积跨槽影响如何处理；损失如何按有效元素归一化；当前输入不能包含未来真值；原1836窗输入/目标不变；不跨演示、不把终帧虚构成新实测数据。先用手算短轨迹和实际边界样本验证这些条件。若尚不能定义有意义的掩码去噪目标，则停在设计层，不以“加一个mask就好了”提交训练。

这是覆盖和监督支持范围的改变，**并非仅增加样本数量的纯单变量对照**。无效槽仍可能通过U-Net卷积影响有效槽，单纯不计损失不足以证明影响消失。协议需在训练前明确这一点，并与已有完整窗口分开报告。

数据入口明确后再制定一次有上限的训练验收：主目标仍是独立演示误差；训练误差只作健康检查，同时报告完整/短未来窗口。夹爪联合训练的完整功能版本与保持位姿损失的覆盖比较要分清，不能一次更改两者后唯一归因；也不能用补齐夹爪代替位姿泛化验收。内部验证用于选模，旧40开发及已看过13验收只作已消耗证据，最终新集合一次验收。具体训练预算、检查点规则和新划分尚未制定，不能宣称正式训练协议已经就绪。

若完成这些仍无改善，保留207558，不自动扩演示、加预算或切数据集。这次先补全训练所对应的任务范围，不承诺能单独消除现有泛化误差。Bridge到仿真仍需单独证明观察、动作和控制接口，不能把这一CPU入口验证或离线误差改善写成抓取成功。
