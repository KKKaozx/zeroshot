## 已核验：未发现所检查窗口的索引错配

从74条选定演示重读168份原始输入，校验原始图像、完整state/action字段和指令哈希。所有窗口图像、语言、当前state使用同一输入索引t，目标来自t+1到t+16；168个窗口均有完整16目标，不靠尾部填充。首末标记和字段长度正确，state/action有限，任务文字匹配。重读图像处理张量及当前夹爪编码与参考精确一致。

用独立float64的`Rz(yaw)Ry(pitch)Rx(roll)`和Hamilton公式，由原始当前/未来state重建全部局部位姿标签：位置分量最大差3.40e-7项目单位（约3.40e-6cm），四元数分量最大差1.38e-7。几何零旋转/同姿态/90度旋转检查通过。这些微小数值差不是厘米级泛化误差。

此结果支持当前代码索引和标签构造一致。选定字段没有明确传感器时间戳，无法独立核验采集时的硬件同步；不同演示的物理基座/相机标定也未提供。xyz米、RPY弧度是项目采用且与原始标签还原一致的解释，不宣称另做了真实机器人物理标定。

## 已确认：完整当前位姿未作为数值条件传入位姿头

| 数据 | 来源与用途 | 当前位姿预测是否显式接收 |
| --- | --- | --- |
| 当前图像 | image_0[t]→CLIP视觉token→Adapter | 是 |
| 当前指令 | language[t]→CLIP文本token→Adapter | 是 |
| 当前末端XYZ/RPY | state[t,:6]用于把未来state转换为局部动作标签 | **没有数值输入到位姿去噪器** |
| 当前夹爪测量 | state[t,6]仿射编码后传给独立夹爪分支 | 不进入位姿去噪器 |
| 真实历史图像 | 本诊断入口两次使用同一当前视觉token | 没有真实前一帧输入 |
| 带噪动作与时间步 | DDPM训练/生成内部变量 | 位姿去噪器输入，不是额外观测state |

这里核验的是冻结201663训练入口，不能扩展成所有项目模式均如此。`context`两次调用同一当前图文Adapter；训练时dropout可使两次输出不同，评估时相同，不能当作两帧真实历史。

源代码证据：`dataset.py:1623`当前位姿用于构造标签，`:1646`同索引图文输入；`fit_bridge_growth128.py:123`实际上下文；`models.py:291`去噪器只接带噪动作、时间步和上下文，`:332`当前夹爪进入独立分支。对源码哈希和实际调用AST进行检查，未修改生产文件。

**缺少显式位姿不等于已经证明输入不足。**图像可能提供部分机器人位姿信息；本次压缩视觉描述符也不能代表完整视觉token包含的全部信息。这是下一项控制变量实验的候选输入差异，不是已定位的CLIP/Adapter缺陷。
