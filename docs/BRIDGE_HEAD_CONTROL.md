# Bridge联合训练：直接回归与扩散方案

准备日期：2026-10-08。当前仅完成本地全数据准备和CPU控制测试，下一步提交GPU预检；尚无这次对照的训练结果。

之前187797比较冻结图文特征下两种扩散降噪器，不能替代此次联合训练对照。190189及后续冻结诊断也不作为本次匹配训练随机流的控制组。本次两组均从头训练，复用190189配置而不加载其可训练权重；CLIP仍加载同一预训练缓存。

## 固定条件

- 使用同一405条训练演示（1836窗口）、10条开发演示（40窗口），保留测试不读取；16个动作目标、原坐标表示和标签规则。
- 同一冻结CLIP、8层Adapter、cls_patch_mean读出、夹爪头及输入。Adapter与夹爪所有初始参数/缓冲区逐项复制并核对哈希；CLIP前后哈希及梯度检查。
- 两组均训练Adapter、对应位姿头和夹爪头；不冻结Adapter、不缓存其可训练输出。
- 使用独立NumPy随机源预先确定20轮逐窗口顺序；每轮每训练窗口恰好一次，batch=2，各18360次更新。
- AdamW、lr=1e-4、weight_decay=1e-4、每轮余弦调度、梯度裁剪1。每次forward前按更新编号重置随机种子，样本顺序不受动作头随机数消耗影响；不声称所有内部随机运算一一对应。
- 固定最终第20轮，开发结果不选checkpoint或修改预算。回归推理确定性评估一次，扩散原100步采样使用0/1/2三个种子；都用归档sample及同一物理评分，报告训练/开发总体、任务及演示指标。

## 有意改变与解释限制

复用归档RobotAdapterModel和policy_loss，不新写网络或损失。回归头使用现有MLP直接输出16个位姿，损失为归一化xyz MSE加符号不变四元数损失；扩散头使用现有U-Net、100步余弦表及x0 MSE。夹爪损失与权重保持原配置。两组容量及位姿损失尺度不同，影响共享Adapter梯度，因此这是两套预测/训练方案比较，不能称为仅采样器消融或等参数量实验。两组均只用一个训练初始化种子，三次扩散采样不是三个训练种子。

如果回归完整训练误差明显降低，说明此数据与视觉条件至少可在替代训练方案下更好拟合，应优先检查扩散目标/优化/采样；不证明某一公式唯一有错。如果回归训练也接近任务均值，不能因此直接判定CLIP或Adapter失效，应进一步检查输入阶段信息与可学习性。开发优势还需按任务及演示检查，不能自动推断机器人成功。

## 两阶段执行和容量

新驱动只负责配对顺序、初始化、训练与记录，调用归档模型/损失/评分函数。提交前校验新小包及原始数据包SHA256。预检每组6次临时更新，验证真实梯度、权重变化、CLIP冻结和8窗口原生采样，预检权重丢弃。根据热更新和采样耗时，给完整两组估计增加50%余量；须低于3小时额度的80%，显存保留量低于设备总量的85%。估计不等于保证。

正式运行要求同一协议、代码和配置的passed预检JSON。用同一入口以train阶段运行时，须在sbatch命令上明确设置--time=03:00:00，默认15分钟仅供预检。此时再确定是否可按实际估计缩短申请时间。当前不提交正式训练。

只在集群保存两份最终可训练权重、小预测数组与JSON，不复制CLIP、数据或环境，不保存优化器历史checkpoint。预计新结果小于1GiB，实际预检会给出可训练参数量；本地只接收小报告。进程被打断需重跑，对照期间不并行启动其他训练。

本地准备已真实读取1876窗口并核对191004清单、归档模块及20轮覆盖，未加载模型。CPU测试验证训练顺序独立性、共用初始模块一致以及两个现有动作头的反向传播，使用小型替代编码器，不视为真实CLIP/GPU通过。
