## 请求与监督

输入仍是当前观察产生的上下文。设K为调用方请求的未来动作个数：

| 请求 | 可用训练输入 | 真正监督 | 生成时 |
|---|---:|---|---|
| K=1 | 候选3394个起点全部可用 | 仅state[t+1]相对state[t]的位姿 | 固定请求下一步；不询问记录剩余长度 |
| K=16 | 原1836个完整起点 | 原16步真实未来位姿 | 保留原16步输出及比较方式 |

清单包含5230个“起点×请求”组合，其中1836个起点同时出现两种请求。这不是5230个独立窗口/演示，不代表已决定其训练权重或算力预算。新增1558个后段起点在本方案中只提供下一步监督，不再声称学习了它们不存在的完整16步未来。

不采用`K=min(16,记录剩余长度)`。真实长度仅用于训练数据资格检查：请求16步却没有16步真实标签时直接拒绝，不自动缩短请求或填标签。请求1步在所有起点都用相同规则；以后部署也可一直请求1步，不需要知道任务何时结束。

**两种请求都运行100次DDPM去噪。** K=1指一条未来位姿，不能与“一次去噪”混淆。若部署采用K=1，应每执行一次动作重新观察；这改变了原一次执行4个动作的控制频率，不能称执行协议保持不变。本原型仅输出7维位姿，夹爪和机器人控制尚未接入，也没有解决任务终止判断。

## 训练和生成使用相同的计算槽规则

U-Net计算形状仍为16×7。前K槽是随机状态，其余是固定零计算槽。零四元数在这里仅是未执行的隐空间占位，不是物理位姿或监督标签；最终API只返回前K个真实请求槽，不让占位槽流入控制器。

令P_K是选择前K槽的投影。训练前向过程为：

`x_s = sqrt(alpha_bar_s) P_K x_0 + sqrt(1-alpha_bar_s) P_K epsilon`

这是K×7个随机维度的扩散过程，嵌入16×7的固定计算空间；未请求维度不再被当成有标准高斯噪声的未知动作。没有真实目标的位置依旧可保留NaN哨兵；先用where投影，再加噪，不做会保留NaN的“乘0”。损失只评价前K槽。

反向过程也从投影后的高斯噪声开始，复用原x0预测、100步余弦表和后验系数；**每次调用U-Net前、预测后和后验更新后都投影**，保证未请求槽保持相同结构零。最终仅对前K槽做位置限制及四元数单位化，返回B×K×7。

原U-Net的卷积和GroupNorm仍看到结构零，因此不能说填充对网络结构完全没有影响。已经消除的是任意哨兵值或随机填充数值的影响；结构零的作用在训练和推理中保持一致，并且网络被告知调用方请求了哪一种长度。

请求条件采用一个无bias的线性投影，将`mask_K-1`映射为上下文偏移。生产1024维上下文需新增16384个参数，零初始化。K=16时偏移恒为零，即使这个投影之后学成非零，保持同一个U-Net权重时原16步映射仍不变。K=1有显式请求条件，不借助记录剩余长度推断掩码。

**这是新增模型条件和训练目标，不是原模型不变的单变量扩窗。** 未来联合优化共享权重仍会改变16步表现，函数兼容检查不能保证训练后不退化。需要在正式设计中区分“新请求目标的影响”与“新增后段输入的影响”。

## 实际CPU验证

使用存档U-Net的同一三尺度代码，缩小通道为[8,16,32]、上下文8维，随机初始化69583参数；没有加载真实策略。另用人工定义的精确干净输出函数检查去噪计算闭合，它不是学习模型。

| 检查 | 结果 |
|---|---|
| K=16的前向加噪、去噪器输出、损失 | 与旧算式/同一小U-Net逐元素相同 |
| K=16与存档sample函数真实AST的100次调用 | 每步含噪输入、时间步、上下文、输出均差0；最终位姿差0 |
| K=1时有效标签从1步改为15步，但首目标不变 | 输入、预测、损失完全一致；多余真值不进模型 |
| 未请求槽的目标/噪声改成NaN | 有效输出和损失不变 |
| 未请求原始输入的梯度 | 0；新请求投影有非零梯度，其余梯度有限 |
| K=1完整100步生成 | 每次U-Net输入的未请求槽都为0，最终只返回1×1×7，四元数单位化 |
| 人工精确干净输出函数的K=1生成 | 与其预先规定的合成目标最大分量差4.17e-6，仅是数值验证 |
| 参数指纹、优化器更新 | 前后参数一致，0次更新 |

首次CPU检查发现按窗口先求均值改变了浮点32归约顺序。原型的K=16分支已改回原F.mse_loss归约，未放宽断言。失败记录保留；它是新原型的数值兼容问题，不能宣称为207558泛化问题的根因。最终检查约0.88秒，不含解释器导入。
