# 当前末端位姿输入：单变量配对协议

目的：检验“只靠当前图像/语言，缺少明确的当前末端位姿”这个候选解释。输入审计已确认状态可用，但尚未证明它是泛化失败的原因。此实验复用201663原始128训练窗/64演示和40开发窗/10演示，不采用202069的39窗替换。

两组使用相同网络和共享初始化，增加同一个无偏置、零权重初始化的9→1024线性状态接口，再把它加到现有图文上下文。唯一处理差异：控制组输入9个零值，处理组输入观测时刻的当前末端XYZ与姿态。零接口初始不改变模型，且短跑须确认控制组的损失、参数、上下文和预测能精确重放旧模型。

## 输入与冻结项

从每个窗口的state[start_index]只取XYZ/RPY六个原始数值。XYZ按128训练窗口的均值/标准差处理，开发沿用同一统计量、不裁剪；姿态用RzRyRx矩阵前两列共六个连续特征，因此最终为9维。包内只有168个当前位姿，没有未来位姿数组、动作答案或演示编号特征。原始state/action身份哈希仅用于验收，不作为网络输入。原有动作表示、尺度和反归一化不变。

CLIP和夹爪保持冻结；八层Adapter、多尺度U-Net、x0目标、DDPM100、batch8、初始化43、全部抽样/噪声种子、8192次更新都不变。前4096次学习率1e-4，后4096次1e-5。每个训练窗口在完整预算中被抽到512次。两组依次运行，在同一张集群GPU上执行。

数值实现：零输入接口的参数梯度严格为零。若把这个零块也加入全局梯度范数的浮点求和，会改变原控制的末位舍入。控制组先断言该梯度全零，再在裁剪范数中排除这个零块，保持原参数的求和顺序；真实状态组正常计入状态梯度。两组仍使用相同Adam和同一数学裁剪公式，没有放宽精确重放门槛。

重复当前图像的历史接口保持原样；本轮没有加入真正的前一帧。状态来自数据集记录的坐标系，没有独立证明不同演示的物理标定一致。本轮只检查这个具体状态注入方案，不同时调整历史、相机、图像预处理或动作定义。

## 执行与验收

本地仅做短预检，不跑8192次正式拟合，不保存PT。预检有三个短运行：旧模型观察器、零状态接口、真实状态接口。每个运行16次高学习率更新，然后从同一Adam状态执行16次继续/恢复/降低学习率对照，共64次短更新；32个训练窗口、三个采样种子、五个预测快照用于接口验收。预检拟合误差不用于判断泛化。

预检必须满足：

- 168个原始输入与201663身份一致；状态来自同一观测索引，只用训练统计量。
- 零状态组所有原模型参数、五份上下文/目标/预测快照及64个更新损失与旧模型精确一致。
- 两个状态组共享初始化、第一步损失一致；真实状态接口有非零梯度，权重和上下文贡献实际改变；零状态接口保持零。
- CLIP、夹爪和其他冻结参数不变；观察器不改变随机数状态；恢复Adam分支精确重放。
- 独立CPU重算15份预测的路径/第16目标误差；真实启动脚本通过参数解析和bash语法检查。

集群预检必须重新通过这些条件。正式脚本同时受Slurm afterok依赖和已成功预检报告门控；只检查Slurm退出码还不够。正式阶段每组完整评估128训练窗和40开发窗，不按开发误差挑选checkpoint。每组仅保存一份训练参数PT，包含状态接口和重建协议。

## 判断和停止条件

执行passed只表示流程与接口检查通过。先确认两组训练拟合门槛，再看完整路径和第16目标，以及逐任务/逐演示结果。

- 两组训练均拟合，处理组开发路径位置和旋转均优于配对零状态控制，并且至少6/10开发演示位置改善：只是候选收益。报告改善的实际幅度；仅允许再做一个额外初始化的完整配对复核。
- 两组均拟合、处理组没有上述收益：停止这个状态方案，不追加层数/权重扫描。
- 处理组未拟合：结果不够回答泛化假设。检查新接口/优化，不能宣称状态无用，也不自动加轮数。
- 位置和旋转平均还须同时优于静止基线，才称本开发协议通过。开发集已反复使用，最终泛化仍须固定配方后在封存演示上评价。

本轮不扩大256窗、不混入新数据集、不进行PyBullet抓取评价；夹爪状态准确率不等于抓取或释放成功。
