# DDPM 与 U-Net 实际运行对照

日期：2026-10-06。此次实际执行项目代码和作者组件，区别于此前只读源码差异清单。结果：[机器可读报告](../reports/ddpm_runtime_comparison.json)。复查入口：[唯一运行对照脚本](../diagnostics/run_author_runtime_comparison.py)。

## 实际运行了什么

- 当前 `code/models.py` 的 `diffusion_loss()`、`sample()`，当前 `ConditionalDiffusionDecoder`。
- 作者固定提交 `5ba07ac6661db573af695b419a7947ecb704690f` 的原始 `ConditionalUnet1D`，未改作者网络代码。
- 作者环境固定的 diffusers 0.11.1 原始 `DDPMScheduler.add_noise()`、`step()`。
- CPU、float32。U-Net 使用相同的 B=2、T=16、7 维动作、1024 维上下文输入。没有优化器或权重更新。

为避免下载/构造 CLIP，调度测试仅绕过 CLIP 构造；从项目构造函数中直接执行实际噪声 buffer 初始化代码，再调用实际训练加噪与采样方法。U-Net 实际完整实例化并计算前向、反向。夹爪分支用固定输出隔离，未验证夹爪学习。

DDPM 的降噪预测器在此明确知道合成干净目标，用于比较计算，而不是证明模型能预测动作。随机数入口在测试范围内替换为相同预先生成的噪声；生产代码、作者网络和库源码都未修改。

## 数值结果

| 项目 | 实际范围 | 最大绝对差 / 结果 |
|---|---|---|
| 100 步余弦 beta 表 | 项目 vs diffusers | 0：本次逐位相同 |
| 训练加噪 | t=0…99；epsilon/sample 两种目标 | 0：本次逐位相同；训练目标精确匹配 |
| 反向采样，无 x0 裁剪 | 每种目标各 100 步 | 9.42e-6 |
| 相同 x0 裁剪 ±1，epsilon | 100 步 | 2.38e-7 |
| 相同 x0 裁剪 ±1，sample | 100 步 | 2.92e-6 |
| 项目 xyz 裁剪 ±3，直接对库原生 ±1 | 边界动作合成案例 | 约 1.00：预期差异，不能宣布数值一致 |
| 显式对齐 xyz ±3 / 四元数 ±1 后 | 每种目标各 100 步 | 最大 2.92e-6 |

项目完整执行 100 次反向调用；参考库每一步接收项目该步实际输入、相同模型输出及相同噪声。因此这里是每步运行等价性，不是两个独立传播的完整轨迹误差测试。t=0 的参考结果应用项目相同的最终位置裁剪和四元数单位化后比较。

反向数值检查预设绝对容差 2e-4，实测最大对齐误差 <1e-5。上述误差是归一化动作分量差，不是已学会机器人控制的误差。浮点运算路径不同，因此不要求逐位一致。

库原生裁剪到 ±1，而本项目 xyz 除以 0.10 m 后裁剪到 ±3；用合成归一化位置 2.0 可以触发这个差异。对齐范围的参考调用显式裁剪 x0，再用库的 `sample` 目标、关闭内部裁剪计算后验；它不是作者默认原生配置。实际部署不能未经尺度核对直接替换默认 scheduler。

作者网络使用所选配置的 [512,1024,2048] 通道、kernel=5、时间嵌入 128，并把本项目固定 1024 维上下文接为 global_cond。它没有加载作者图像编码器，也不是默认 Robomimic 观测维度的完整策略。因此参数量只对应此次明确输入配置。

两套网络随机初始化且结构不同，没有进行输出相等的错误断言。它们接收相同数值输入；相同初始化 seed 不意味着参数相同。梯度通过仅说明计算图连接，不证明语义信息充分、训练能收敛或哪套泛化更好。报告中的秒数是本机一次诊断耗时，不是推理性能基准。

## 环境和复查

作者组件的旧依赖与当前 Transformers 不兼容。此次使用 `training_cache/references/ddpm-runtime-env` 隔离环境，共享本机 PyTorch 2.11.0+cu128，但在子环境安装 diffusers 0.11.1、huggingface-hub 0.11.1、Transformers 4.25.1、tokenizers 0.13.3。einops 0.8.2 来自现有环境。当前训练环境的包版本保持。

这不是复现作者完整 Python 3.9/PyTorch 1.12.1 的旧训练环境；它是固定旧调度库与原网络在当前 PyTorch 下的 CPU运行测试。未下载模型、训练数据或启用 GPU。

本机项目根目录 PowerShell 复查命令：

```powershell
& '.\training_cache\references\ddpm-runtime-env\Scripts\python.exe' diagnostics/run_author_runtime_comparison.py
```

其他机器需先准备可用 PyTorch/NumPy/einops 环境、固定版本作者仓库及上述隔离依赖。不要直接在当前训练环境降级 Transformers 或 huggingface-hub。

## 能支持的结论与下一步

这次为“当前被测 DDPM 路径能与库实现对齐”提供了实际运行证据，也验证了两个降噪器的形状、条件传递和梯度。没有发现新的被测公式错误。

不能由此排除所有实现问题，不能证明作者网络优于当前网络，也不能证明当前泛化失败来自容量差异。下一次如要比较学习效果，应保持数据、动作契约、上下文、采样范围和优化预算明确，实际训练两种降噪器并评价；本轮没有执行该训练。
