# 从 Bridge 诊断转入正式实验

日期：2026-10-06。依据老师四封邮件，以第四封的数据来源/版本说明为准。当前为阶段协议，不是可直接执行的训练配置；没有启动训练、下载数据或运行模型仿真。

## 已结束的诊断与仍需完成的目标

固定 Bridge 单任务诊断已完成：独立数据核验、完整训练拟合、当前/作者动作头检查及有限学习率补充。作者低学习率最终训练为 0.115 cm / 0.442°，开发为 10.170 cm / 15.445°，没有一条开发演示同时超过两项静止基线。停止重复这条参数调试路线。

正式目标是冻结 CLIP、联合训练 8 层/512 注意力通道 Adapter 与扩散动作解码器，在 LIBERO/CLIPort 上测任务成功率、语言变化及跨机器人迁移。旧 2 层/256 通道冻结上下文实验没有验证这一完整模型；使用更深 Adapter 本身也不是解决泛化的保证。

## 首要入口门槛：动作含义一致，而不只是数组维度相同

现有接口证据见 [formal_protocol_interface_evidence.json](../reports/formal_protocol_interface_evidence.json)。只读取一个 CLIPort 训练示例与一个 LIBERO 文件的形状/控制器元数据，未使用最终测试目标指标。

| 路径 | 原生或当前含义 | 正式训练/评估前要解决的事项 |
|---|---|---|
| Bridge 当前诊断 | 输入时刻末端坐标下的未来实测位姿，xyz 除以 0.1 m；命令夹爪 ±1 | 现行数值合同已核验；真实控制与时间延迟尚未验证 |
| CLIPort 官方环境 | `pose0`/`pose1` 两个世界位姿交给任务 primitive | 原生拾取/放置接口与连续轨迹不同，不能直接把 16 个 Bridge 位姿交给 `env.step` |
| CLIPort 统一加载路径 | 原有 `_append` 已排除 CLIPort；旧 `_get_cliport` 曾合成四个绝对事件位姿 | 原有训练不会经该路径混入 CLIPort；现将旧函数改为明确报错，原生读取单独检查 |
| 本地 LIBERO 示例 | Panda、7 维原生动作、`OSC_POSE`、`control_delta=true` | 8 维未来位姿不是原生 7 维控制命令，需要有定义和验证的转换接口 |
| Language Table real | 推杆，不具备一般夹爪语义 | 无观测自由度必须用监督掩码/能力定义；不能填常量后当成真实旋转/夹爪监督 |
| BC-Z / RT-1 | 原始状态与控制命令需逐版本核验 | 固定单位、坐标、旋转、夹爪、时序、控制能力后才能共同训练 |

CLIPort 示例中 pose0 的 x 为 0.41875 m，属于世界坐标。上一版文档把旧 `_get_cliport` 的函数体当成可进入训练的路径，这一判断不准确：已有 `_append` 会排除 CLIPort。现有训练没有经该路径混入这些标签；旧函数的潜在绕过调用现已被阻止。这不能解释只训练 Bridge 的历史失败。没有可靠输入末端参考位姿时，不能把未来拾取点当作当前末端参考，也不能凭空补出连续轨迹。

资料：[CLIPort 官方环境](https://github.com/cliport/cliport/blob/master/cliport/environments/environment.py)、[LIBERO 官方包装器](https://github.com/Lifelong-Robot-Learning/LIBERO/blob/master/libero/libero/envs/env_wrapper.py)。这是当前源码核对，正式执行前还需固定具体提交版本。

第一步的交付物应是“每个来源的原生动作→统一学习目标→原生执行动作”合同及往返检查。明确时刻/帧、控制频率、相机、缺失自由度、夹爪符号和有效监督掩码。未通过的来源不能以“8 维可加载”作为正式就绪证据。

## 环境与工程正对照

先处理已有 CLIPort 训练任务 `stack-block-pyramid-seq-seen-colors-train` 的接口，不增加任务或网络。保留原生 primitive 与世界位姿，不让当前加载器的四个合成位姿伪装成真实逐帧控制记录。具体统一策略需由上述合同确定后实现。

随后在作者环境验证记录动作或 oracle 能执行、成功判定能读取，再验证经过项目转换的同一动作能保持相同任务行为。这是接口工程正对照，不是运行失败的 Bridge 策略，不是零样本成功率。只使用工程训练分区的固定实例；回放失败时修接口，不训练模型补救。

CLIPort 使用其原生 PyBullet 环境与任务；LIBERO 使用其原生 robosuite/MuJoCo 环境。当前自建 Franka PyBullet 原型不能冒充两者的官方基准。第一阶段不安装全部环境或同时调两套控制器。

## 第一轮完整模型学习：无增强基线

接口和分区准备完成后，才进行一轮无增强完整模型试运行。不是再次把旧 25 条单任务数据交给更大网络。

模型固定为已有冻结 CLIP ViT-L/14、8 层 Adapter、512 注意力通道、DDPM 条件 U-Net；Adapter、动作解码器及需要的夹爪读出共同训练，不复用旧冻结上下文来代替 Adapter 训练。来源原生能力不同的监督掩码必须正确传递。

本地 CLIP 配置实际为视觉 token 1024、文本 token 768、共享投影空间 768。当前代码将视觉/文本分别投影到 512 的注意力空间，再输出 1024 上下文。应如实报告 native token 与投影维度，不写成两个原生编码器都输出 1024；若老师要求额外统一 1024 层，需要另行说明，不暗中增加层。

先以一个独立训练 seed 做资源和执行预检，再按正式要求使用独立训练 seeds 42/43/44。采样 seed、数据划分 seed、环境 seed 独立记录，三个模型共享相同数据划分。实际学习率、更新预算和评估频率在资源预检后一次固定，不能把作者冻结头的 3e-5 或 9,875 次预算照搬成联合训练的最优设置。

训练输入来源按老师最后说明：BridgeData V2 0.0.1、Language Table real、BC-Z 1.0.0、fractal20220817_data。先在已有文件上完成逐来源合同与任务/语言清单；第一轮多任务调试可用预先固定的小型清单，但必须报告实际覆盖数，不能声称达到老师要求的最终数据规模。自然语言与模板语言分开统计。不在动作合同未完成时简单拼接这四个来源。

## 划分、零样本与开发选择

- 按完整演示分区，重叠窗口不跨区；按场景/物体/指令目标定义进一步留出，不能把演示留出当作未见任务留出。
- Bridge 的原 3 条验证是反复检查的开发数据；原 5 条留出不再进入调试。新的正式基准划分、任务名单、语言类别及指纹在训练前固定。
- 最终评估任务/目标/物体的语言改写或反事实样本不得进入训练；同义改写也要按来源目标隔离，不能只按字符串去重。
- 如用 LIBERO/CLIPort 演示训练或做目标域适配，该结果标为域内工程对照或适配结果，不能标为 OXE→未见目标基准的零样本。
- 模型选择只用单独开发任务与预定验证指标；最终固定权重后才评估测试任务。训练损失和离线动作误差作为诊断，主要指标为任务成功率。
- 跨任务、跨物体、跨语言、跨机器人分别定义，不将它们混为一个“泛化成功”。RT-1 与原 CLIPort 的相同任务/观测/控制接口可复现性需要先核对，不能搬用不同论文设置的分数。

## 通过门槛与停止条件

工程接口：示例输入/输出单位、坐标、旋转和夹爪往返一致；记录动作/原生 oracle 的执行与成功判定可复核。能力缺失、时序错误或执行映射失败时停止模型训练。

完整模型无增强基线：先确认联合训练可执行、梯度落到正确模块、CLIP 参数保持不变，并在工程域内正对照上有可复核行为。只证明域内可学还不能宣布 OXE 跨域成功。预先固定验证任务、相同初始状态与基线的配对评估，达到预定任务成功率比较后才扩展研究变量。具体任务数量和门槛需在接口与可用基线确定后填写；现在没有证据支持编造 80% 或 90% 目标。

一轮预定预算没有产生可靠验证行为时停止，不追加任意轮数、不解封最终测试、不开始四组增强。报告失败及范围限制，并向老师说明拟继续的范围。

## 后续正式矩阵，不提前同时启动

基线完成后，按老师要求做无增强、仅五条同义改写、仅反事实、两者组合四组，独立训练 seeds 至少三个；固定相同数据、模型与预算。反事实必须确实与当前场景目标不匹配，不能把仍可执行的另一目标标成无动作。相对位姿的无动作为 xyz=0、四元数 identity，夹爪保持当前状态；不得把全零四元数当合法无动作。该实现与老师描述的字面“零序列”差异要说明。

LIBERO 与 CLIPort 每个任务划分按老师要求 100 个 rollout，报告任务成功率、训练 seed 均值/标准差和逐任务结果；环境初始状态计划固定并共享。seed 之间、任务之间与 rollout 之间的统计层级分开，不能把 300 个 rollout 当成 300 次独立训练。RT-1/原 CLIPort 同协议对比、Adapter 深度消融、跨机器人单独留出、改写分布图及失败图例仍属于必做最终目标。
