# 控制器期望位姿经过8维表示的工程验收

在既有、已排除正式40任务评分的LIBERO90工程demo_0上，实际读取原生控制器期望位姿，转换成当前3+4+1编码，再经原几何函数和执行器运行。保持原演示20Hz时钟，不使用神经模型，不训练，不访问正式评估初态，不重跑已有原生命令成功基线。

## 最终结果与边界

最终attempt7在186个原生步达到原生任务成功判据，关抽屉及碗在柜顶两个子判据均true，随后按既有执行器规则提前停止。已执行的夹爪命令前缀与原专家逐项一致；不表示已执行专家197步的全部末尾命令。

原先固定的所有门槛通过，没有放宽：

- 实际控制器目标最大位置差1.8315e-9米，小于原1e-6米门槛；最大朝向差3.0918e-9弧度，小于原1e-5弧度门槛。
- 8维编码/解码的数值往返通过，实际命令无饱和。
- 回放只恢复一次初态，中途没有按专家状态纠正。提取标签时另有197次记录状态恢复、0物理推进，不能把它们称为自由回放。
- 实际EEF相对原记录轨迹平均位置差0.283mm、最大0.539mm；这与“控制器目标数值一致”是不同指标，不能把1e-9米写成机械臂物理精度。

这只证明该工程案例的**原生20Hz期望控制位姿可以经8维格式保留任务行为**。此前更密的20Hz到达位姿oracle也成功过，所以不能据此声称期望位姿在所有条件下优于到达位姿；也没有证明5Hz足够、当前两个学习模型泛化改善，或四个OXE来源已经具备统一的控制目标。

## 本次明确补齐的接口事实

控制器使用grip-site朝向，观测字段使用hand-body朝向，两者在本机器人上相差固定90度。控制器绝对目标必须先转换到观测所用的朝向框架再编码；这处混用出现在本次新诊断的attempt2中。对于正确构造的左乘相对旋转，固定右侧朝向偏置会抵消，不能把这90度差直接当作原主模型的旋转错误。

恢复初态后，控制器缓存位置与当前状态相差17.01mm、朝向相差约0.0528弧度。普通观测末端字段及未经刷新派生位姿，与当前控制状态也有较小差异。最终原型先执行不推进时间的`sim.forward()`，再从该状态读取控制用位置/朝向，并在发送命令前刷新控制器运动学。由此将目标构造和原生控制放在同一状态；没有修改增益、边界或时间频率。

`sim.forward()`对自由关节四元数产生最大2.22e-16的数值归一化变化；它不推进仿真时间。早期新增的“qpos逐位不变”诊断断言不适用于此处，后续记录该变化而非声称它为零。原任务成功及控制目标门槛保持原值。

本原型没有学习策略。以后如接入真实模型，必须分清“与输入图像时刻对应的固定参考位姿”和“执行命令时的新鲜当前位姿”，不能简单把两者都替换成当前状态，破坏原标签含义。当前正式执行代码、原评估程序、权重和训练标签均未改。
