# 固定5Hz信息的插值对照：没有修复任务失败

本轮只有一个预先固定的新条件：相同工程初态、同一组5Hz专家未来端点、相同的原生20Hz夹爪时刻，将原来的整段追同一个目标改为区间内平移线性插值和旋转Slerp。每0.2秒只调用一次目标提供者，子目标由区间起点的实际EEF与已有端点计算，没有额外提供专家中间位姿。原控制器、边界、坐标转换及200tick预算均保留。

六项新增合成边界检查通过：世界目标不随跟踪滞后漂移、一次高层请求对应四tick、原端点及时间不变、原生成功提前停止、预算不足在调用前拒绝等。最初测试报告写入遇到NumPy bool序列化问题，转换为Python bool后通过；该问题没有进入真实物理运行。

## 源码与已有轨迹的进一步只读复核

原生OSC的位置设定点由`当前测量位置 + 缩放后的专家动作`得到，再由位置/速度误差计算控制力。当前训练标签则由`记录的未来实际到达位置 - 记录的参考位置`构造。这是两个不同的量，后者不是前者的逆变换。

对该工程演示中196个连续行（排除缺少上一帧的首行），按现有控制器公式推算的原生期望设定点，与记录的下一帧实际到达位置平均相差21.51mm、最大41.20mm。这不表示原专家动作错误：动态、阻抗控制中设定点和实际位置本来就可能不同；它说明不能在未经轨迹跟踪验收时，把到达位姿标签直接当作等价控制命令。

因此，当前应优先明确“模型预测的是未来运动结果，还是可直接执行的控制目标，以及中间由哪种跟踪器承担转换”。这是目标定义与部署接口的验收问题，不应继续用更换骨干、追加训练或扩大成功率统计代替它。

## 下一步及边界

停止本插值分支，整理各训练来源的观测位姿、原始动作、坐标/单位和时间含义，核对当前8维目标定义及部署解释之间尚未成立的对应关系。先确定需要修标签、执行层还是研究假设，再提出单一可验收修改；不凭本例直接将主模型改20Hz，不自动重训或恢复大评估。

该问题仍不足以解释所有跨域失败；模型源内动作能力与跨机器人标定仍未验收。已训练权重、冻结评估程序及既有首回合记录全部保留。seed43现有集群作业没有修改。
