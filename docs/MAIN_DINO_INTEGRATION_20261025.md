# 主项目 DINO 接入结果

2026-10-25。按照第七封邮件推进DINO主方案，新增可显式选择的主训练与推理路径。没有提交集群任务，没有优化器更新或物理仿真，也没有修改既有Push-T包和已训练权重。

## 已完成

- `RobotAdapterModel`新增DINO视觉分支，使用已验证的冻结DINOv2 ViT-L/14本地资产，保持1024维CLS及patch特征；文本仍是冻结CLIP。Adapter、扩散后端、动作表示和夹爪头不因视觉切换而改结构。默认CLIP分支保留，正式DINO需显式选择。
- 主CLI支持`--visual-backbone dinov2 --dino-assets <本地目录>`。DINO分支不隐式下载，检查固定版本的权重、配置及处理器文件SHA；训练配置记录视觉身份和输入约定。固定更新模式将新视觉代码加入恢复身份校验。
- 保留Dataset和LIBERO回调共同使用的`prepare_image`：224双线性等比缩放、CLIP均值补边。DINO内部将这个规范化张量统一转成ImageNet均值/标准差；不额外裁剪视野、不再缩放一次。不修改Dataset，因此动作/窗口解析也不受视觉切换影响。
- 这不是直接移植Push-T的PIL双三次处理器：主项目原来的几何处理保留，DINO与CLIP主实验共享几何和补边，原生通道归一化不同。正式论文与实验配置须如实记录此区别。
- LIBERO的主检查点加载器新增显式`local_dino_path`，拒绝缺少DINO资产、身份不符、CLIP/DINO模式混用；视觉与文本持续冻结。DINO视觉字节身份可验证，但旧主检查点缺少完整CLIP文本资产身份绑定，当前metadata对此仍标为未完全验证。

## 新增路径检查

本机实际加载预训练DINO和CLIP文本权重，使用一层Adapter、32维注意力和小动作头的随机工程模型，完成12项新增接线检查。白色图像的DINO归一化与解析值最大差为0，矩形图补边保持约定；主loss反向传播到Adapter/扩散/夹爪头，两个编码器不产生梯度且参数版本未改变。保存并重新加载随机主检查点后，LIBERO策略回调与直接主模型采样逐元素相等，调用方CPU/CUDA随机状态不变。

实际成功检查耗时13.55秒，峰值保留显存3.350GiB。它不是正式八层模型的显存/吞吐预检，不验证任务成功率、数据物理单位或真实机器人映射。没有更新参数，随机工程检查点不能作为论文模型或部署权重。

成功前的检查修复也保留记录：首次本地GPU环境没有SciPy，后续用结构化执行请求夹具隔离回调检查；未安装包或重复旧执行器检查。第二次发现当前Transformers的`CLIPTextModel`本身就是可调用文本编码器，修正旧式`.text_model`取法，并加入缺失/不匹配权重拒绝。完整CLIP资产中的视觉与投影键在文本专用加载时显示unused/unexpected属于预期；文本参数没有缺失。

证据：`reports/main_dino_integration_20261025/attempt3/report.json`。此前失败发生在成功检查之前，没有训练或产生任务指标。

## 距离正式首组还缺什么

1. 正式OXE训练池与数值动作资格。当前45,049窗口仅来自原32分片工程缓存；单位、时距和坐标/TCP合同仍有缺项，现有索引仍然只允许prepare-only，没有移除防止误训练的限制。
2. 将真实训练检查点的目标时间与LIBERO执行映射接通；本次只验证主模型回调，未运行物理环境。
3. 固定共同结构/来源采样/预算/目标任务协议，并做一次该正式配置的资源和恢复短预检；本轮不重复旧模块检查或追加拟合。
4. 无增强首组应能独立于改写库完成情况启动，但要共享最终固定数据资格；增强语料与反事实未知夹爪规则仍并行准备。
