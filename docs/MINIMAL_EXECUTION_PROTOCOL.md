## 一个候选循环

保留模型预测的 16 步轨迹，候选部署每次只执行第 1 行，随后重新取得观测再预测。预测长度为 16，执行长度为 1，两者必须分别记录。此选择用于先减少旧预测在状态改变后的连续执行；还没有实跑，不是已验证的改进。

1. 在仿真 tick=t 暂停推进物理时间，采集同一状态的 RGB、任务语言、当前 tool_tip link 位姿及末端状态。所有字段带相同 tick；记录相机配置。
2. 用训练时的图像预处理和 tokenizer 前向计算 CLIP、Adapter、动作头，得到 `[1,16,8]`。CLIP 本地运行；CPU/GPU 推理壁钟时间另记，不冒充真实实时控制。
3. 检查完整预测形状与有限值，并按检查点合同校验将执行的第 1 行：位置单位/范围、单位 xyzw 四元数、开合命令、TCP 工作空间。不合格就记录失败并停止该 rollout；不裁剪、不跳过、不重采样挑一个通过的结果。
4. 第 1 行相对于本次观测的 TCP 锚点解码。只执行这一行，使用 `ContinuousTCPController.execute_fixed_period`：默认 0.2s、实际 96 个 1/480s 物理步、现有 0.01rad 关节指令步幅。期间保持请求，尚未激活的关闭请求每物理步重试；打开则释放。不能等到到达再延长周期。
5. 到期丢弃其余 15 行，记录实际位姿、跟踪误差、请求/激活/附着状态。按预先固定的评分频率调用原生 task.reward/task.done，更新语言目标；从当前状态开始下一次观测与预测。

当执行长度将来改为大于 1，同一个预测块内的全部目标仍相对于同一输入 TCP，不能逐行重设锚点。新预测才取得新锚点。不得使用存储的未来真实位姿、专家阶段、对象目标位置或吸盘事件时刻替代模型输出。

原生 `env.step(None)` 会等待物体静止并增加物理步，不能用它刷新固定周期观测。候选观测入口是只渲染的 `_get_obs()` 与当前 TCP 状态查询；评分入口直接使用 task.reward/task.done。这些入口与调用顺序仍需在工程对照中确认。原生 max_steps 以 primitive 为尺度，不能直接当作 0.2s 控制周期数；正式 runner 前必须声明物理时间预算、评分频率、终止条件和结束时是否保持控制。

尤其是 `bridge_measured_affine_unbounded_v1` 的当前夹爪输入，不能直接用吸盘激活布尔值或请求 ±1 冒充 Bridge 的实测连续开度。不存在依据时必须阻止该检查点进入机器人执行，不靠硬填数值绕过。现有 `from_action_config` 只检查几何，不是完整迁移验收器。

保持默认范围不变，作者原命令包含低于零的 tool_tip 目标，不能拿它们强行构造默认工作空间的通过结果。没有网络 TCP 输入不自动构成错误；控制端解码需要当前 TCP，不等于必须增加网络状态输入。

## 验收顺序和停止条件

| 阶段 | 应交付的证据 | 通过后允许做什么 |
| --- | --- | --- |
| A：合同检查 | 相机、夹爪、时钟、TCP、检查点配置、评分和时间预算全部明确 | 构造一个几何合法的工程抓取放置对照 |
| B：固定周期工程执行 | 不恢复状态、不放宽范围/时间/速度，运动和吸盘联合执行；单独报告跟踪、正确对象附着、释放与任务评分 | 实现上述每次执行一行的循环 |
| C：重新观察工程循环 | 每次新观测新锚点，不照搬记录的恢复动作；完整记录奖励、物理时钟和失败类型 | 在合同兼容时做一次模型连通性检查 |
| D：模型连通性 | 真实网络输出驱动控制，没有未来真值或专家动作替换；只是接口测试 | 规划正式训练与独立评估 |
| E：正式评估 | 正式分区、独立训练种子、公平基线、规定任务/rollout 数 | 报告任务成功率或零样本结论 |

当前停在 A/B 之间，不能直接启动 D/E。阶段 B/C 的工程策略若使用对象真值或作者 oracle 必须显式标注，不能写成模型成功。本文没有给失败的 Bridge 检查点放行；泛化与控制两条证据链分别验收。

连续 TCP 控制改动了作者原生 primitive 协议，结果须标为自定义 CLIPort 环境工程协议。原版 CLIPort 基线使用 pose0/pose1，不能将它与自定义连续协议的成功率直接并列当作公平比较；后续需共同协议或明确不同协议及其限制。
