# 模型输入与基准动作合同核对

2026-10-06。本次是现有源码与本地 CLIP 配置核对，外加一次合成坐标数学检查。没有加载网络权重做预测，没有训练，没有仿真，也没有泛化实验。机器可读证据见 [model_benchmark_action_contract.json](../reports/model_benchmark_action_contract.json)。

## 模型实际输入与输出

| 项目 | 主实现的实际含义 | 证据位置 |
| --- | --- | --- |
| 图像 | 单张 RGB，保持比例缩放/补边到 224×224，再按 CLIP 均值方差归一化 | `dataset.prepare_image` |
| 语言 | tokenizer 产生 token ID 和 attention mask；文本长度上限 77 | `train.py`、本地 CLIP config |
| 视觉特征 | ViT-L/14 的 257 个 token，每个 1024 维（224/14 的 16×16 patches 加 CLS） | CLIP config、`models.get_context_vector` |
| 文本特征 | 文本 token 的 768 维隐藏特征；不是每个 token 1024 维 | 同上 |
| Adapter | 视觉查询文本 token；默认 8 层，Q/K/V 投影到 512 注意力通道；输出 1024 维上下文 | `adapter.py`、`models.py` |
| 机器人状态 | 主上下文未接收当前 TCP 位姿；可选当前夹爪值仅进入夹爪预测支路 | `models.forward/get_context_vector/predict_gripper_logits` |
| 动作 | 通常为 `[B,16,8]`：相对输入时刻末端的 xyz、xyzw 四元数、开合命令 | `dataset.relative_pose_action`、`models.sample` |

本地 CLIP 的联合投影维度是 768；主实现使用编码器隐藏 token，不能把联合投影维度和视觉/文本隐藏维度混为一谈。表中的 token 数与特征宽度由配置及调用路径推得，不是本次网络前向运行测量。

默认架构不等于已有实验架构。近期 Bridge 头部诊断使用的是冻结的较小 Adapter 上下文，仅训练动作头；此前还做过独立的当前位姿输入实验，但不能把那条诊断支路当作主实现已经具备的功能。没有当前 TCP 输入不自动构成错误，也不能据此认定其为泛化失败根因。

Bridge 解析器用输入时刻的 TCP 位姿构造标签，但正常 batch 不把该位姿作为模型输入返回。标签使用的信息与模型输入的信息必须区分。部署时把相对输出还原成世界位姿，则仍需要控制端取得真实当前 TCP 位姿，并核对同一末端参考点。

## 这些 16 个目标不是连续增量

所有目标都相对于同一张输入图像时刻的末端位姿，而不是相对于前一个预测目标。设输入世界 x=0.10 m，两行归一化 x 分别为 0.5、1.0，则目标是 0.15 m、0.20 m。逐行累加会错误地到达 0.25 m。

恢复世界位置的关系是：`p_target = p_input + R_input × (0.10 × local_xyz)`；旋转是 `q_target = q_input × q_relative`。自建 Panda 原型保留了同一动作块的固定参考点，但它不等于 CLIPort 官方执行接口。

本次实际运行了旋转参考系下的编码→解码：位置误差约 2.98×10⁻⁸ m、考虑 q 与 -q 等价后的四元数向量误差约 6.14×10⁻⁸。它仅验证几何公式在该合成例子上的一致性，不验证网络输出、TCP 标定或运动控制精度。

## 与 CLIPort 的缺口

| 合同 | 当前 Bridge 模型 | CLIPort 作者环境 |
| --- | --- | --- |
| 观测 | 一张 RGB 与语言 | 三个相机 RGB-D；模型应使用哪些视角尚未定义 |
| 位姿参考 | 输入时刻工具坐标系；xyz 除以 0.10 m | 世界坐标米制 `pose0/pose1` |
| 时间含义 | 16 个未来到达位姿，不保证包括完整抓取和放置阶段 | 一次调用执行整个拾取/放置 primitive |
| 末端控制 | -1 关闭、+1 打开；Bridge 测量与命令分开 | UR5 吸盘，由 primitive 执行接触检测、吸附与释放 |
| 动作接口 | 数组 `[16,8]` | 字典 `{"pose0": (xyz,xyzw), "pose1": (xyz,xyzw)}` |

**当前模型输出不能直接传给原生 `env.step`。** 还原世界坐标只解决了参考系，未解决拾取/放置目标选择、完整操作阶段识别、吸盘语义、步长/时长与 TCP 标定。取数组的第一行和最后一行当 `pose0/pose1` 没有依据；16 个目标也不能简单 reshape 成两个位姿。

原生回放成功只说明作者动作字典在该场景可执行，没有验证上述桥接。原生数据读取已经与统一 OXE 训练分开；当前统一加载器仍排除 CLIPort。不能用原生 CLIPort 演示训练新动作头后，将结果标为 OXE→CLIPort 零样本。

## 下一步需要先定的接口

保留老师要求的连续轨迹解码器时，必须明确基准评估是否允许连续末端控制入口，以及观测、控制周期、吸盘与基线如何保持一致。若坚持作者两位姿 primitive，则需要一个可论证并验证的轨迹→primitive 转换；当前尚未实现，不应假定任意预测轨迹都包含两者。

给老师确认的具体问题可以是：

> 我的 OXE 模型输出 16 个相对末端目标，而 CLIPort 原生环境接收世界坐标拾取/放置两个位姿。最终评估是否要求使用原生两位姿接口，还是允许定义连续末端控制接口？相应的 RT-1/原 CLIPort 基线应如何对齐？

这份核对明确了部署接口缺口，不解释或解决已经观察到的 Bridge 离线泛化失败。本次不修改网络、目标维度或成功标准，也不启动新训练。
