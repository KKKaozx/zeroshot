# 模型输入与基准动作合同核对

2026-10-06。本次是现有源码与本地 CLIP 配置核对，外加一次合成坐标数学检查。没有加载网络权重做预测，没有训练，没有仿真，也没有泛化实验。机器可读证据见 [model_benchmark_action_contract.json](../reports/model_benchmark_action_contract.json)。

## 模型实际输入与输出

| 项目 | 主实现的实际含义 | 证据位置 |
| --- | --- | --- |
| 图像 | 单张 RGB，保持比例缩放/补边到 224×224，再按 CLIP 均值方差归一化 | `dataset.prepare_image` |
| 语言 | tokenizer 产生 token ID 和 attention mask；文本长度上限 77 | `train.py`、本地 CLIP config |
| 视觉特征 | ViT-L/14 的 257 个 token，每个 1024 维（224/14 的 16×16 patches 加 CLS） | CLIP config、`models.get_context_vector` |
| 文本特征 | 文本 token 的 768 维隐藏特征；不是每个 token 1024 维 | 同上 |
| Adapter | 视觉查询文本 token；默认 8 层，Q/K/V 投影到 512 注意力通道；输出 1024 维上下文 | `adapter.py`、`models.py` |
| 机器人状态 | 主上下文未接收当前 TCP 位姿；可选当前夹爪值仅进入夹爪预测支路 | `models.forward/get_context_vector/predict_gripper_logits` |
| 动作 | 通常为 `[B,16,8]`：相对输入时刻末端的 xyz、xyzw 四元数、开合命令 | `dataset.relative_pose_action`、`models.sample` |

本地 CLIP 的联合投影维度是 768；主实现使用编码器隐藏 token，不能把联合投影维度和视觉/文本隐藏维度混为一谈。表中的 token 数与特征宽度由配置及调用路径推得，不是本次网络前向运行测量。

默认架构不等于已有实验架构。近期 Bridge 头部诊断使用的是冻结的较小 Adapter 上下文，仅训练动作头；此前还做过独立的当前位姿输入实验，但不能把那条诊断支路当作主实现已经具备的功能。没有当前 TCP 输入不自动构成错误，也不能据此认定其为泛化失败根因。

Bridge 解析器用输入时刻的 TCP 位姿构造标签，但正常 batch 不把该位姿作为模型输入返回。标签使用的信息与模型输入的信息必须区分。部署时把相对输出还原成世界位姿，则仍需要控制端取得真实当前 TCP 位姿，并核对同一末端参考点。

## 这些 16 个目标不是连续增量

所有目标都相对于同一张输入图像时刻的末端位姿，而不是相对于前一个预测目标。设输入世界 x=0.10 m，两行归一化 x 分别为 0.5、1.0，则目标是 0.15 m、0.20 m。逐行累加会错误地到达 0.25 m。

恢复世界位置的关系是：`p_target = p_input + R_input × (0.10 × local_xyz)`；旋转是 `q_target = q_input × q_relative`。自建 Panda 原型保留了同一动作块的固定参考点，但它不等于 CLIPort 官方执行接口。

本次实际运行了旋转参考系下的编码→解码：位置误差约 2.98×10⁻⁸ m、考虑 q 与 -q 等价后的四元数向量误差约 6.14×10⁻⁸。它仅验证几何公式在该合成例子上的一致性，不验证网络输出、TCP 标定或运动控制精度。

## 与 CLIPort 的缺口

| 合同 | 当前 Bridge 模型 | CLIPort 作者环境 |
| --- | --- | --- |
| 观测 | 一张 RGB 与语言 | 三个相机 RGB-D；模型应使用哪些视角尚未定义 |
| 位姿参考 | 输入时刻工具坐标系；xyz 除以 0.10 m | 世界坐标米制 `pose0/pose1` |
| 时间含义 | 16 个未来到达位姿，不保证包括完整抓取和放置阶段 | 一次调用执行整个拾取/放置 primitive |
| 末端控制 | -1 关闭、+1 打开；Bridge 测量与命令分开 | UR5 吸盘，由 primitive 执行接触检测、吸附与释放 |
| 动作接口 | 数组 `[16,8]` | 字典 `{"pose0": (xyz,xyzw), "pose1": (xyz,xyzw)}` |

**当前模型输出不能直接传给原生 `env.step`。** 还原世界坐标只解决了参考系，未解决拾取/放置目标选择、完整操作阶段识别、吸盘语义、步长/时长与 TCP 标定。取数组的第一行和最后一行当 `pose0/pose1` 没有依据；16 个目标也不能简单 reshape 成两个位姿。

原生回放成功只说明作者动作字典在该场景可执行，没有验证上述桥接。原生数据读取已经与统一 OXE 训练分开；当前统一加载器仍排除 CLIPort。不能用原生 CLIPort 演示训练新动作头后，将结果标为 OXE→CLIPort 零样本。

## 下一步需要先定的接口

保留老师要求的连续轨迹解码器时，必须明确基准评估是否允许连续末端控制入口，以及观测、控制周期、吸盘与基线如何保持一致。若坚持作者两位姿 primitive，则需要一个可论证并验证的轨迹→primitive 转换；当前仅有受限的工程原型，尚未验证模型输出；不应假定任意预测轨迹都包含两者。

已按用户要求自主推进，不以询问老师作为前置条件。先实现严格原生事件转换并检查适用范围；随后依据数据证据选择连续末端控制路线。具体依据见下节。

这份核对明确了部署接口缺口，不解释或解决已经观察到的 Bridge 离线泛化失败。本次不修改网络、目标维度或成功标准，也不启动新训练。

## 自主实施结果与路线选择

在现有 `dataset.py` 增加 `trajectory_to_cliport_primitive`，沿用固定参考系和 0.10 m 缩放：拾取点取唯一开→关事件对应的目标，放置点取其后的唯一关→开事件目标。要求实际初始吸盘命令为打开，二值命令、合法单位四元数和完整单周期；缺少释放、多个周期、初始已关闭、非二值命令均拒绝执行。不随意选首尾端点，也不补造操作阶段。

适用前提是事件目标确实表示吸盘接触/释放位姿，不能仅因符号相同就宣称 Bridge 的夹爪命令与吸盘等价。该原型不进入统一训练加载，不连接现有失败模型。

12 项合同测试通过，原数据模块的 15 个既有顶层定义 AST 未变。以作者端点及人工给定的阶段标签构造 7 个合成 16 行轨迹，转换后在当前训练场景执行，总奖励 1；世界位置往返最大误差约 2.22×10⁻⁷ m。它只验证转换函数和作者执行接口在已知目标上的组合，**没有模型预测，也不是泛化实验**。

实际适用范围检查：

| 已缓存 Bridge 真值窗口 | 数量 | 假设初始打开时恰好包含一次关闭后打开 | 不依赖初始假设、窗口内完整开→关→开 |
| --- | --- | --- | --- |
| 训练 | 316 | 16 | 0 |
| 开发验证 | 55 | 2 | 0 |

这是标签序列的语法计数，不能当成可执行抓取覆盖率；连续夹爪测量不能确定先前吸盘命令。7 个工程轨迹中的 6 个还超出现有模型的 xyz ±3 归一化裁剪范围。转换对照没有施加该裁剪，不能把其成功移植为当前模型可以覆盖同样端点。

**自主选择：保留 16 步连续轨迹输出，后续构建连续 TCP 控制协议。** 原生事件映射保留为有限工程对照，不能作为默认部署方案。原因是多数真实窗口没有完整拾取/放置周期；不通过盲加轮数、强行补释放动作或直接放宽裁剪来解决接口问题。

连续控制原型已经使用作者 UR5/吸盘资源实现；仍须固定动作块的输入 TCP 参考系，明确动作时长、控制预算、观测视角、末端参考点和当前吸盘状态编码。该连续协议与原生 `env.step(pose0,pose1)` 有区别，必须如实标注并对齐基线，不能称为未经修改的官方 CLIPort 协议。工程对照发现插入笛卡尔中间点会破坏该场景，详见 [执行隔离结果](CLIPORT_NATIVE_EXECUTION.md)。尚未接入学习模型或验收正式控制协议。

## 动作范围与控制接口约定（2026-10-06 后续）

重新计算完整缓存，并核对已有分布报告：训练 5,056 个目标中 20 个目标、10 个窗口超出归一化逐轴 ±3；最大幅值 3.284484。开发 880 个目标均在范围内，最大 2.791508。默认尺度仍为 0.10m，逐轴 ±3 表示输入工具坐标系内每轴 ±30cm，不是总移动距离 30cm，也不是控制器每次推进 30cm。

训练标签未裁剪，而模型在采样中及最终输出使用该界限。单目标最大不可避免位置误差约 2.84484cm，全训练目标平均下限仅 0.004728cm。此前 5 个未通过的拟合窗口中，90、235、241 有越界目标，247、327 没有；不能把全部残余误差或约 10cm 的开发误差归因于裁剪。这是对已有发现的复核，不是新的泛化根因。证据：[范围与接口核验](../reports/model_controller_range_contract.json)。

接口采用以下约定：

- 控制器从模型配置核对动作表示、0.10m 尺度及明确声明的归一化界限，不使用另一套静默默认值。`ContinuousTCPController.from_action_config` 已实现；实际缓存配置检查通过，模型权重未加载或执行。
- 整个块保持一个输入 TCP 参考系；合法目标直接交给作者 `movep` 的逆运动学及关节运动。控制器不为满足数值界限补造笛卡尔中间点，也不裁剪越界目标。
- 后续训练必须先核验所选训练目标与声明的采样界限一致；若不一致，应先明确协议变更，不能裁剪真值后宣称拟合成功。现有缓存、权重、默认界限 3 均未修改；不依据测试数据选范围。
- 几何配置一致仍不能证明 Bridge 到达位姿等于仿真控制命令。控制时间、TCP 标定、夹爪测量与吸盘命令的区别仍须单独验收，不能直接启动学习策略 rollout。

新增两项几何配置拒绝/界限继承测试，读取、转换及控制合同合计 21 项通过。没有新训练、数据集或权重下载。
