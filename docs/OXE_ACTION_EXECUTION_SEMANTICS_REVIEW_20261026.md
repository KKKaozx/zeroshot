# OXE标签与LIBERO执行：四来源语义复核

本次只读实际标签生成、训练消费和执行代码，复用已有来源溯源及工程诊断。不重新扫描数据、不加载模型、不运行仿真、不训练、不提交作业。它补齐的是主链路含义审阅，不是新的性能结果，也不重复此前单位/时钟调查。

## 当前模型究竟预测什么

当前正式模型消费 `NominalOXEDataset` 的已绑定目标文件，而非旧加载器中可选的原生动作分支。16个目标对应名义未来0.2至3.2秒：位置为 `(未来观测位置－输入观测位置)/0.1`；旋转为 `q_future × inverse(q_reference)`，xyzw；最后一维是经过来源转换的开正夹爪命令。所有目标相对同一个输入时刻，不是16个可逐项累加的增量。

因此，前七维描述未来观测的运动结果，夹爪维描述命令，整体是混合语义的轨迹表示，并非原生控制器动作的可逆重新编码。使用未来观测构造监督目标本身不属于输入泄漏；历史夹爪输入与未来监督必须分开审查，已有因果输入检查仍有效。

| 来源 | 实际运动标签来源 | 原始动作/目标字段的使用情况 | 名义时钟与未核实项 |
|---|---|---|---|
| Bridge 0.0.1 | `observation/state[:3]`及XYZ Euler转四元数 | 原始7维action只取夹爪；前六维不作为本次运动监督 | 5Hz，未来每一源行；精确导出位置单位、时间间隔、源基座/TCP到LIBERO对应未核实 |
| Language Table 0.1.0 | `observation/effector_translation`的实际XY | `effector_target_translation`不作为本次目标；不存在夹爪监督 | 5Hz；仅XY受监督，z/旋转/夹爪全部mask；实机XY单位、轴和精确导出时间未核实 |
| BC-Z 1.0.0 | `observation/present/xyz`与绝对轴角转四元数 | `future/xyz_residual`和`future/axis_angle_residual`不作本次运动监督；仅取各源区间的`target_close`首槽 | 10Hz按每两源行取5Hz目标；原生未来10槽不能直接称为本模型16个时间目标；缓存版本与公开0.1.0说明的等价关系、单位及时间未核实 |
| Fractal 0.1.0 | `observation/base_pose_tool_reached`，代码按xyz+xyzw解析 | 本次不以原生平移/旋转命令构造运动标签；夹爪由相对closedness命令转绝对开正命令 | 名义3Hz插值到5Hz，没有增加真实时间信息；精确导出的四元数顺序、单位和记录间隔仍缺独立来源证明 |

每个来源原始位置均保留自身坐标。0.1是记录数值的归一化除数，不会自动完成毫米到米转换。当前训练协议明确选择“把原始XYZ当米”的研究假设，同时保留 `exact_export_units_verified_for_all_sources=false`；这不能写成单位已经标定。没有逐帧时间戳，名义频率也不能写成精确实测时距。

## 与执行端尚未成立的对应

1. **到达结果不是控制器设定点。** LIBERO把解码后的世界目标，经当前位置误差和原生OSC尺度转换为命令，每个20Hz tick重新反馈。原生OSC设定点是“当前实测位置＋缩放后的命令”，并非下一帧必然达到的位置。已有工程演示中两者平均相差21.51mm，这种动态/阻抗差异本来就可能存在。不能由此断言未来位姿预测错误，但必须由独立轨迹跟踪层证明接触行为仍可完成。

2. **共享坐标命名不等于跨机器人标定。** 当前解码直接将预测位移乘0.1米加到LIBERO世界EEF位置，并把预测相对旋转左乘到其朝向，没有源机器人到目标机器人轴变换。若同一物理点的源坐标到目标坐标为旋转A、单位换算s，至少应满足 `delta_p_L = s*A*delta_p_S`、`delta_R_L = A*delta_R_S*A^T`；当前近似相当于单位换算1和A为单位阵。不同TCP物理点还可能需要额外处理。这里说的是未验证的约定，不是已证明每个来源坐标都错。

3. **命令时刻与位姿时刻不同。** 标签在未来端点附近取一个源区间夹爪命令，执行器则从0.2秒区间开始就发送它；不能保证保留区间内部切换时刻。已做工程对照恢复精确原生夹爪时刻后仍失败，所以不能把该单例全归因于夹爪。5Hz姿态端点也不保留所有接触过程；Fractal的上采样不能补回原本未记录的过程。

## 已排除的误读与证据限制

- 不是所有来源把Euler/轴角原样当四元数：Bridge和BC-Z明确转换；Fractal按xyzw读取的代码事实不等于其精确缓存顺序已被独立证明。
- Bridge已有推导证明：若 `R_recorded=R_tool*D^T`，且D在同一演示内固定，则左乘相对旋转中的D抵消。旧工具坐标表示的问题不能直接套到当前源坐标表示。
- Language Table缺失的六维没有当作真实零值/打开标签监督；已有mask和缺失夹爪输入规则沿用。
- 现有归一化、有限值、四元数单位长度、数据隔离及身份校验通过，只证明相应数值/来源条件，不证明物理语义与跨机器人执行成立。
- 已排除工程任务中，原生动作回放成功；5Hz正确未来位姿通过当前执行链仍失败；更密20Hz专家目标成功；同信息量单次插值仍失败。这支持“当前执行链尚未保留已知任务行为”，不证明所有5Hz方法不可能，不证明正式首回合失败全由此造成，也不证明泛化已修复。

## 工作决策

继续暂停新条件/种子和批量LIBERO评分，保留已训练模型、现有seed43作业及首回合有效失败；不再扫描插值、增益、频率或追加训练预算。Push-T仍只支持视觉骨干选择。

下一项优先补齐**可执行动作合同**，而非增加算法变体：对现有四来源逐一取得精确版本的单位、轴/TCP、观测与命令时序依据，并明确项目输出定位为“未来到达轨迹＋经独立验收的跟踪器”还是“有来源依据的控制目标”。原生动作字段不能直接跨机器人照搬；也不能先把标签换成原生命令再用一次长训练碰运气。

目前缺少的外部事实不能靠代码检查凭空补齐。若现有原始数据和发布说明无法建立这些对应，应将“零样本跨机器人执行需要哪些标定/适配、是否允许独立控制适配层”作为具体研究设计问题交给老师确认，而不是改成LIBERO演示训练后仍称原来的零样本实验。源内固定验证窗解码仍是后续独立学习诊断项，尚未执行，不把本次语义复核算作其结果。

2026-10-26从老师邮件DOCX正文只读提取英文原文核对，不依据后续中文摘要反推要求：

- 第一封英文正文第25段的主问题明确是少量OXE训练后，对LIBERO/CLIPort新物体及指令测零样本任务成功率。第28段要求统一语言、RGB和8维位姿动作格式，但没有规定“未来观测到达位姿等价于原控制器设定点”，也没有给出跨机器人坐标变换。
- 第三封英文正文第8段另要求单一机器人训练到另一机器人评估，并与同机器人基线一起报告。第四封第4、8、10、12段明确主训练四来源及版本、Language Table只用实机并披露棍状末端差异；选择正确数据版本不等于单位和执行标定已经完成。
