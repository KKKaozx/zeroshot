Language Table的本地数据名称`language_table`及442,226条计数与[作者说明中的real来源](https://github.com/google-research/language-table#datasets)相符；不是`language_table_sim`。该身份依据不等于已验证所有本地记录内容。

## 当前不能直接混合的原因

| 项目 | 已有证据 | 仍要解决 |
| --- | --- | --- |
| 坐标 | Bridge/BC-Z/Fractal已有到达位姿数值还原检查 | Language Table仅xy且无朝向，当前解析器用单位朝向占位；尚不能证明其xy与共同工具坐标轴一致 |
| 夹爪输入 | Bridge、BC-Z、Fractal提供实测量；Language Table提供占位 | 统一“binary”标签不足以区分测量与命令，还缺缺失输入表达和跨来源标定 |
| 夹爪目标 | Fractal相对命令重建及BC-Z前一命令策略已验收 | 新训练必须显式选择`relative_scan_v2`、`preceding_command_v2`，不能继承旧默认标签 |
| 时间 | 现有16目标是未来观测到达位姿 | 不同来源同一行号未必对应相同秒数，尚未绑定部署时间合同 |
| 数据隔离 | 新候选未读取最终任务目标，保留旧Bridge身份排除 | 需原演示/共享帧分组，再划分源内训练与验证；Language Table重标注片段尤其不能仅按记录随机切分 |
| 训练入口 | 主模型、部分监督mask和四语言条件已有代码 | 还需明确主runner的解码器配置、完整状态恢复和固定更新预算；模型类支持某结构不等于CLI已接通 |

[作者Language Table环境](https://github.com/google-research/language-table/blob/main/language_table/environments/language_table.py)观测只保留末端平移的前两维，仿真控制采用固定朝向。**不能据此把仿真固定朝向当成本地真实机器人朝向。** BC-Z的[官方字段定义](https://www.tensorflow.org/datasets/catalog/bc_z)也明确区分`sensed_close`实测闭合度与`target_close`绝对目标命令。维度或取值范围相同，不说明语义相同。

本次没有把这些混源缺口称为Bridge历史泛化根因：Bridge207558没有使用这四来源混合训练。

## 已收紧新推理入口

上一步新增的LIBERO推理入口原先只检查`current_gripper_encoding=binary`，不足以支持它使用“上一条命令”的假设。现增加明确的`current_gripper_semantics=last_command_open_positive_v1`要求，缺少声明时拒绝。旧模型若实际用实测状态训练，不能仅补一个配置字段就改变训练含义。主训练器目前没有自动生成这个命令语义声明，因此其旧checkpoint不会被新入口自动认作命令条件模型。

仅对这个新条件补查了原小模型接口测试，检查通过；没有重跑学习、示范回放或泛化实验。真实混源训练必须先确定输入特征语义，再选择训练和部署共同遵守的实现。

## 下一步及预算

机器可读方案见[阶段配置](../configs/oxe_no_augmentation_stage_plan_20261020.json)。下一项限定为共同夹爪输入（观测/命令/缺失）和Language Table坐标接受条件，完成后才按原始演示分组固定划分、枚举窗口。若来源尚不兼容，保留为待接入，不能悄悄丢掉该来源后宣称完成老师的四来源要求。

正式四条件共享样本和分区，训练seed42/43/44独立。来源均衡各25%仅为待定方案；实际窗口数、有效监督维度和runner性能明确后，一次固定批量、学习率与更新预算。目前未填写臆测的正式步数或生成可提交训练命令。

更新预算为U、batch为B、来源采样比例为p时，该来源预期样本访问约U×B×p；再除以该来源有效窗口数才得到每窗口平均访问次数。这个关系用于报告预算，不保证每个窗口访问相同，也不代表同等梯度权重——Language Table只监督2维，而其他来源可监督完整位姿/夹爪。

候选清单是第一批工程池，不代替老师要求的最终大规模训练。全量四来源超出此前200GB SSD配额，最终需要另外落实流式或分批存储。Push-T214273继续原计划，207558参照及最终LIBERO/CLIPort目标不改。
