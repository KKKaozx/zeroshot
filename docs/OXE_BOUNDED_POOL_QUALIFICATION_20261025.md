# 容量受限候选池的记录与训练目标审核

2026-10-25。对已固定的15.896GiB、128分片候选清单开展一次身份扫描，随后只审核冻结训练角色的数值目标。没有复制分片到集群、加载模型、优化参数或运行物理仿真。

## 记录与共同分区

128个TFRecord分片的CRC检查、记录数和容器长度均通过，与发布元数据的12,931条记录一致，耗时131.02秒。哈希原始编码图片而不解码像素；按同来源的原始身份和共享JPEG建立传递关联，并纳入以前5,158条工程记录的角色锚点。

新池共12,814个候选内容组，其中198个与旧分区关联。一个Language Table关联组同时连接旧train与test，涉及两条新候选，因此整组候选隔离，不重新分配旧角色。这个发现说明旧LT工程组的独立性不能仅凭此前有限范围的共享检查认定；本轮没有修改历史实验结果。新池只对无旧角色锚点的组使用原80/10/10函数和seed42分配，三训练种子及全部13次条件共用。

## 训练侧数值结果

在分区固定之后，审核10,340条train记录。检查实际使用的位姿/命令数组形状、有限值、非缺失方向、原始指令、当前命令因果输入，以及原有Bridge命令扫描。通过8,918条记录，对应146,287个候选训练窗口。

| 来源 | 数值通过的train记录 | 窗口数 |
|---|---:|---:|
| Bridge | 1,151 | 10,352 |
| Language Table | 2,565 | 12,214 |
| BC-Z | 2,739 | 96,271 |
| Fractal | 2,463 | 27,450 |
| 合计 | 8,918 | 146,287 |

沿用既定16个未来目标、输入步长4、演示最少10行，尾部补齐不增加监督。因此不是每帧都作为输入，也不是14.6万条独立演示。每来源4GiB只是存储配额，不能当成四源训练暴露量相同；正式采样比例仍须显式固定。

排除规则在数值读取前写入：Bridge有429条输入窗口缺指令、7条过短、9条无法按既有扫描规则产生二值夹爪目标；LT907条、BC-Z54条、Fractal16条过短。“过短”只是未达到既定规则，不代表演示任务失败。没有根据模型误差、动作大小或任务难度删样本。

对每条数值通过的train记录，用实际Dataset解析器检查首/尾窗口，共17,836个探针；只替换图片解码与预处理为占位输入，位姿、夹爪和mask路径仍为生产代码。全部使用到的源数组也作了域检查，不能把首尾探针描述成每个中间窗口都逐一调用了Dataset。数值审核耗时125.94秒，读取约12.19GB训练payload，不读取validation/test/隔离记录的数值标签，不解码图片。

原始训练指令与窗口身份已同时记录为JSONL，后续文本整理可复用，避免重读原数据。本轮不生成改写或反事实语言。

## 正式配置需要收敛的两点

第一，旧主入口的位置输出限制写死为归一化±3，但本池合格训练标签最大约9.596。各来源超过±3的监督位置分量比例为Bridge0.0324%、LT1.2950%、BC-Z0.0215%、Fractal3.2857%。这是当前数学除数0.1下的训练侧统计，不是经过单位核验的物理距离，也不是留出误差。

已加入显式`--max-normalized-position`，默认3保留历史兼容性，拒绝非正值与NaN/Inf，DINO恢复时不能改变该值。小型固定干净预测夹具验证：旧3按原规则裁剪，显式10保留9.596的预测。当前算术约定下10可作为候选值，正式值须在源单位与统一尺度固定后重新确认；没有修改旧权重、推理算法或直接宣布泛化改善。

第二，3D训练窗口中有15,155个当前夹爪命令未知：Bridge1,376、BC-Z2,739、Fractal11,040。它们可以保留原专家动作进行无增强训练；但反事实“不动”不能为它们伪造保持开/合标签。LT的12,214个窗口没有夹爪，其相关维度一直屏蔽。反事实适用范围或缺失监督规则要在正式条件协议中确定。
