# 四来源笛卡尔位移动作接口：默认关闭的新表示

2026-10-20。解决Language Table没有工具朝向时的表示接入，不是Bridge泛化根因判定，也不是已经完成新的四来源训练。

## 表示选择的依据与边界

本地Language Table真实数据只有源坐标XY；现有工具坐标表示需要参考工具朝向，不能用单位四元数补出标定。此前查到的[作者公开资产](https://github.com/google-research/language-table)和[论文第V节](https://arxiv.org/pdf/2210.06407)不足以给出适用于这批实机记录的工具旋转矩阵，仿真固定常量不作实机证据。

因此增加明确、默认关闭的**新动作表示**，四来源一同采用源记录的笛卡尔位移，不仅给Language Table换含义。代码`code/cartesian_action_contract.py`：

`source_cartesian_delta_pose_open_positive_v1`

- 位移：`(p_future - p_observation) / 0.10`，保留各来源记录的位置坐标轴，不再旋转到当前工具轴。
- 旋转：`q_future × inverse(q_observation)`，以源坐标左乘差表示；解码时`q_future = delta_q × q_observation`。
- 夹爪：原先已明确的绝对开正闭负命令；未知输入仍使用`[0,0]`。
- Language Table：仅源XY是真实监督，其他输出维度继续屏蔽；构造XY不需要末端朝向。

这只统一动作的**定义与接口**，没有把不同机器人的物理坐标轴、相机视角、工具中心点或控制频率校准为相同。并未由此证明跨机器人泛化更好。各源位置单位、朝向字段的坐标定义和部署时间仍需来源依据；不能将未完成的物理核对写成已标定。

## 实际接入范围

主训练入口新增`--action-frame source_cartesian`，必须同时显式使用`--oxe-command-input`；旧默认仍是`tool`。Bridge、BC-Z、Fractal的实际到达位姿解析器都通过新编码函数，保持图像、语言、夹爪命令及其因果输入策略。其他来源不自动开放，原生控制命令诊断不转入新表示。

真实Language Table还必须指定`--language-table-groups`，绑定上一步的真实缓存身份/共享帧组清单。清单外记录拒绝；每次载入的原始TFRecord payload SHA必须匹配分组记录；`group_key`采用共享帧连通组，避免已发现的别名记录被随机分到两侧。清单是已有缓存范围，并不支持拿仿真记录换个名称进入训练，也不证明已排除所有原始采集别名。

新模式把短窗口末尾的补齐槽位mask置零，对所有四来源一致生效；存储可以重复末项，但重复值不再作为额外真实目标计入损失与指标。旧模式保持原有行为。

数据身份加入新表示和LT组清单SHA；配置记录新表示及左乘旋转含义。新模式检查点保存全部窗口身份，恢复时在加载主干前核对表示、样本身份与组清单SHA，即使样本数量不变也不能更换分组。恢复或初始化时坐标表示不一致会被拒绝，不能将旧工具坐标权重直接标记为新模型继续使用。此处只验收数据/表示绑定，不等于主runner的完整优化器/RNG步数恢复已经验收。

LIBERO几何转换、时间执行合同及主模型回调同时支持该表示：源位移在LIBERO中对应观测所用的世界坐标位移；相对旋转左乘参考姿态。检查点、执行合同和请求的表示必须匹配。这个执行器需要完整3D模型预测；附带部分监督mask的平面源标签不能解码为完整目标。裸8维数组没有能力mask，调用者仍须区分真实标签占位与完整模型输出。

## 验证结果

[检查脚本](../scripts/check_oxe_cartesian_interface_20261020.py)和[报告](../reports/oxe_cartesian_interface_20261020/report.json)：

- 三个完整位姿源9个合成窗口，使用非零且变化的参考旋转；新表示解码回原始未来位置/朝向。旧默认解析、配置、数据身份及原生动作保持一致。
- 两个平面合成窗口及已检查过的一个真实Language Table记录，补查新的源XY编码；实际payload身份匹配，篡改预期SHA被拒绝；旧工具模式和缺失分组清单仍拒绝LT。
- 实际主损失在11个混合合成窗口上，只有222个有效位姿分量、30个有效夹爪时间步参与梯度；缺失维度和补齐槽位没有直接监督梯度。
- 64组随机参考姿态/非交换旋转，实际robosuite OSC `set_goal`与新目标的最大位置差约`3.70e-10 m`、朝向差`9.12e-9 rad`。这是几何实现一致性，**不是模型预测误差**。
- 合成反馈执行确认工具转90度后仍按源X方向移动；回调使用固定采样器桩检查表示/缺失输入接线，没有加载神经策略或预训练CLIP。
- 主训练实际恢复判断、检查点/执行合同/请求错配和带mask的平面标签执行拒绝通过。

没有优化神经模型、进行MuJoCo物理步、读取最终任务标签或提交作业；CLIP、Adapter和降噪网络实现未修改。Push-T214273、Bridge207558及已冻结集群包不变。

## 下一项

新接口已经解除“没有朝向就只能伪造工具轴”的软件限制，但正式训练仍未就绪。下一项是复用现有记录验收与重叠组，落实四来源单位/帧与时间依据、原始演示别名处理以及固定分区；新坐标下的训练目标范围也需要记录，不能照搬旧工具坐标的逐轴统计。然后确定共同时间窗口、来源监督权重和固定步数训练/完整恢复预算。不会为了验收该接口再做一轮记忆拟合或重跑已关闭的Bridge改进分支。
