# 下一项候选：当前配方的中等规模训练能力

用户已选择约26分钟新预算，代码包与13项CPU检查完成，尚未上传/提交或执行真实GPU。233531轮转分支仍关闭；本组只复用原有放回控制。运行代码见[代码与提交说明](OXE_COMPETENCE_POOL_CODE_20261029.md)。

## 要回答的问题

旧 DINO Bridge 配方能学习，当前四源配方固定 8 个 Bridge 窗口也能明显拟合；这些正对照不重跑。233531 当前 14,336 步在抽查训练窗上仍弱，误差下降伴随幅度收缩。下一项有价值的问题是：保持当前全部网络、监督和优化设置，能否在一个具有多演示多来源变化、但可充分重复的有限训练池上学到正确运动？

候选池共 **512 个训练窗口，四来源各 128 个，来自各自 128 个不同组**。每来源保留原来在 231297 之前已冻结的 8 个训练评价窗口，另按预声明 seed 从其他训练组抽 120 组、每组一个窗口。选样不使用目标值或误差，不接触验证组选择。训练评价锚点是有意反复训练的行，用来测训练能力，不能当泛化样本。

## 复用与预算

- 从 232587 real_pose 10,240 步恢复核心、位姿端口、三组 Adam 和 RNG。
- 只新增一组 4,096 步，到 14,336 步；对照直接复用 233531 的有放回组，不重训。
- 两组均有放回抽样，保留每一步来源槽位、批大小、原 Linux LR、77 token 训练补齐。不是追加轮转变体。
- DINO/CLIP 文本冻结、CLS 读出、x0、U-Net、当前位姿、标签/掩码、夹爪损失和裁剪均不改。
- 根据 233531 实测，候选训练约 22 分钟，保守计入原模型重放和评价约 **26 分钟**，不含排队和部分启动核对。用户已另行选定这笔新预算；尚未提交。
- 代码已要求从已保存控制组完整轨迹核对实际模型 RNG、扩散噪声和时间步；CPU 计划本身不证明这些量一致。两组会是不同作业分配，不能称同 allocation。

## 端点与解释

优先看原 32 个已见训练评价窗，按来源报告轨迹/终点位置和旋转、方向与幅度，比较源模型、旧等预算对照和不动。该来源四个有监督均值均优于不动才称该组基本训练能力得到支持，LT 仅比较 XY 两项。仍报告原 88 个开发窗，但不据此挑选样本、预算或模型。

若训练端有改善，说明当前配方在这个有限多来源池上能学习，有理由优先讨论主训练规模、预算和优化阶段；不能证明这些是完整池问题的唯一原因。若失败，不自动减小池、删来源、换 loss/骨干/LR、追加步数或种子。无论哪种结果，均不是论文主模型或 LIBERO 放行凭据。
