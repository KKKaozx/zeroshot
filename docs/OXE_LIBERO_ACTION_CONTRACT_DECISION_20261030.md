## 建议保留的研究定位与两条实施路径

论文主问题保持OXE训练、LIBERO目标评估，冻结DINOv2/CLIP文本、Adapter与扩散动作后端。默认继续使用用户已同意的名义时钟作为披露约定，不因本次收敛要求重新找所有时间戳。

**优先考虑路径A：未来到达轨迹＋明确的目标机器人跟踪层。** 与现有监督含义一致，先澄清共同坐标/TCP与状态输入，再评估执行器需要什么信息。若最终定义完全不变，现有权重作为对应历史模型保留；若改了源坐标、TCP或统计定义，不能声称旧权重已按新合同训练。现有5Hz执行器没有准入，不因路径选择自动恢复使用。

**路径B：有来源依据的控制期望目标监督。** 只有精确导出字段确实定义了控制目标时才可采用；必须同时写明单位、轴、期望位姿/增量、时距和夹爪。它改变标签语义，需新数据版本、源能力配方及重训预算。不能直接照搬各源原生动作，更不能用一次长训练判断它是否合理。

当前不选择一个未经验证的控制算法，也不把“改成20Hz”列为修复方案：20Hz专家成功条件额外知道密集正确轨迹；仅改调用频率不产生这些信息。

## 最小公共字段：缺失值必须保留为空

应先确定一个公共坐标/物理点C，分别定义四来源S→C和LIBERO T→C。混合模型不能在部署时任意挑一个训练来源的基座当成公共世界。

1. **空间与单位：** 每来源的位置单位比例、轴旋转、原点/工作区对应，以及记录的是哪个EEF/TCP物理点；目标侧同样明确。不得默认全部取单位阵/比例1并改写为“已校准”。若继续采用工程约定，应明确它是限制而非事实。
2. **当前状态输入：** 目标当前实测位姿先转换到训练约定的公共坐标/TCP，再按冻结的训练统计构造18D输入；不能只改输出而保留不一致的绝对状态输入。独立port权重、统计与训练合同一起恢复，不能丢弃port或重拟合目标统计。
3. **输出：** 说明预测量为实测未来到达结果还是期望控制目标；明确固定参考与旋转乘法顺序、归一化除数、未来时刻和夹爪生效规则。
4. **执行：** 说明目标机器人控制频率、反馈观测、限幅与接触时序的处理；哪些信息属于实际部署可用输入，哪些仅属于工程oracle。不能让未来专家信息进入正式策略。
5. **验收与范围：** 源能力和执行能力分开报告；正式40任务不用于挑控制参数；目标示教不进入主策略训练。普通控制接口/已排除样例的工程验收已有用户授权，不重新虚构“所有本地工作必须等审批”的门槛。改变标签含义、引入目标监督或缩减原研究范围则需明确说明。

在同一物理参考点且忽略TCP偏移的简化刚性对应中，若`p_T = b + s A p_S`，则目标输入反变换为`p_S = A^T(p_T-b)/s`，输出位移为`delta_p_T = s A delta_p_S`。若姿态对应为`R_T=A R_S C`，输入还需右侧工具轴对应C，而左相对输出满足`delta_R_T=A delta_R_S A^T`。这些公式只说明**需要哪些参数**，不提供参数值；TCP不同还含随姿态变化的位置偏移项，不能只用一个固定平移代替。没有实现一个假设参数全为单位值的通用适配器。
