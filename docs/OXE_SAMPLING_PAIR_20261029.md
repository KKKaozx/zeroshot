# 当前 OXE 来源内抽样对照（2026-10-29）

用户选择约 45 分钟、每组 4,096 步。代码已准备，尚未提交；集群排队不计入估计。作业上限 60 分钟，每组训练最多 2,100 秒，2,048 步保存完整断点。固定 77 token 的训练补齐可能增加耗时，不能把估计当完成保证。

## 问题与控制

比较同一来源内部的有放回随机抽样，和无放回洗牌轮转。保留四来源共 145,812 窗口，每个批次的来源槽位、批大小、两组总更新数和原学习率完全相同。两组平均每窗口增加的呈现次数相同；测试的是重复分布与覆盖，不是增加平均练习次数。

恢复 232587 的 real_pose 10,240 步模型，分别继续到 14,336 步。保留核心和位姿支路权重、三组 Adam 状态、源 RNG；不用后来只记忆 8 窗口的 233426 权重。DINOv2-L/14、CLIP 文本冻结，x0、当前位姿、标签、掩码和夹爪损失均延续该源模型。

两组都使用 77 token 训练补齐，控制 attention/dropout 张量形状；这是相对旧动态补齐的共同调用变化，因此因果比较只在本次两组之间成立。实际每步的扩散噪声、时间步与前后完整模型 RNG 仍须一致，不能靠补齐规则推断。标签不同，含标签的 noisy_actions 和梯度不要求相等。

| 来源 | 两组新增呈现数 | 有放回不同窗口覆盖 | 轮转不同窗口覆盖 |
|---|---:|---:|---:|
| Bridge | 8,287 | 55.5% | 80.1% |
| Language Table | 8,091 | 48.2% | 66.2% |
| BC-Z | 8,081 | 8.10% | 8.44% |
| Fractal | 8,309 | 26.1% | 30.3% |

轮转队列从干预起点重新建立，不声称旧前缀也采用了轮转。此短预算不完成全池训练；BC-Z 两组覆盖差别很小，阴性结果不能排除完整预算的覆盖收益。

## 准入与评价

提交前 CPU 读取真实集群源断点：核对核心/位姿/合同摘要，实际 order 和身份训练索引映射，下一段全部 32,768 索引及 4,096 个实际 Linux 学习率；逐批核对来源和掩码。沿用已通过的源加载函数，只复用其已有学习率引用修复，不依赖旧失败日志，不放宽守卫。

正式优化前按原编码/批次规则重放 120 窗口 × 3 采样种子，必须与 232587 原预测完全一致。再对两组真实首批做零优化步的随机流检查。每组保存核心、位姿、Adam、RNG、轨迹和显式干预计数；恢复前验证历史前缀，不改写旧主实验日程。

端点使用原 32 个训练窗口和 88 个开发窗口，主要看 64 个不同 Bridge 开发组。完整 DDPM 100 步、相同 3 采样种子；报告两组、源 10,240 步和不动基线。源模型更新数不同，只作为退化参照。抽样效应与优于不动的基本能力分开判断，并列出其他来源退化。重复开发组、单个训练种子不构成最终泛化结论。

本地 CPU 测试使用真实数值目标、原损失/100 步采样和替身编码器，覆盖配对随机流、完整断点恢复、原 120 窗输入准备、保存后核验及错误拒绝。没有本地真实 DINO/CUDA 训练；集群上的源重放和随机流守卫仍是必需检查。
