## 时间与单位证据

核对准确的本地TFDS元数据并保存SHA。文献/作者代码能支持以下名义频率，但不能直接证明当前缓存每条导出记录等间隔：

| 来源及本地版本 | 文献描述的名义频率 | 依据及限制 |
| --- | ---: | --- |
| Bridge 0.0.1 | 5Hz | [原论文3.1节](https://arxiv.org/pdf/2308.12952)；[作者评估代码](https://github.com/rail-berkeley/bridge_data_v2/blob/main/experiments/eval.py)也使用0.2秒周期；尚未绑定该TFDS导出的逐帧间隔 |
| Language Table real 0.1.0 | 5Hz | [原论文V节、附录C](https://arxiv.org/pdf/2210.06407)明确区分真实采集5Hz与仿真阻塞控制10Hz，不能用仿真频率代替真实数据 |
| BC-Z 1.0.0 | 10Hz | [原论文4节](https://proceedings.mlr.press/v164/jang22a/jang22a.pdf)描述非实时控制；[当前TFDS目录](https://www.tensorflow.org/datasets/catalog/bc_z)记录的默认版本0.1.0与本地1.0.0不同，不能仅凭字段相似就确认转换链完全相同 |
| Fractal 0.1.0 | 3Hz | [RT-1作者项目页](https://robotics-transformer1.github.io/)给出策略闭环指令频率；这尤其不等于已证明Fractal导出观测严格每1/3秒一帧 |

四个本地feature schema都没有逐帧时间戳。**同样16个未来行号不代表已建立共同物理时间范围。** 仅作为名义频率示例，16个间隔分别约3.2、3.2、1.6、5.33秒；这些数不作为本地记录已经验证的真实时间，也没有据此执行重采样。

位置字段的本地说明尚不能单独证明其到“米”的完整转换链。BC-Z文档能支持robot-frame位置、Fractal能支持base-relative位姿，但不能将数值大小合理、往返计算正确或旧代码变量名含meters当作独立单位标定证据。已把“文献名义频率”“导出记录间隔”“源字段物理单位”“跨机器人TCP/轴映射”分开记录，未填写假通过结果。

证据：[逐来源元数据、字段说明和参考链接](../reports/oxe_units_time_evidence_20261020/report.json)。没有换归一化尺度、估计归一化参数或改动算法。
