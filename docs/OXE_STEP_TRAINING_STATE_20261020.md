# 固定更新与断点恢复组件验收

2026-10-20。落实原计划中的独立训练工程项。新增组件和合成验证脚本；现有`train.py`、模型、数据加载及执行接口均未改动，尚未接入真实主训练入口。

## 已实现

[组件](../code/step_training_state.py)提供：

- 固定总优化更新数。分段停止点与总预算分开，恢复时拒绝修改总预算。
- 独立采样随机生成器，支持无放回打乱与显式权重的有放回采样；保留每一遍末尾的短批次。保存当前抽样序列、遍历位置及完成更新数。
- 单批预留/提交：优化器更新完成后才提交游标，未提交的批次禁止保存断点，避免把预取当成已经训练。
- 按完成更新数确定学习率，显式给定基础学习率、恒定/余弦策略及预热范围；分段恢复不会重开或延长调度周期。这是新组件的明确算法，未替换旧epoch策略。
- 保存并恢复Python、NumPy、Torch CPU以及显式启用的全部CUDA随机状态。构建/载入模型和优化器后最后恢复随机状态，避免初始化消耗影响下一批噪声。
- 同目录临时文件写入、刷新后原子替换断点；恢复前检查训练合同、采样合同、调度范围、优化器学习率与环境设置。
- 模型状态由调用方显式提供。验证中只保存合成网络的可训练头，未把冻结编码器重复存入权重。

该组件不会自动推断CLIP身份、窗口身份或语言库。实际runner必须把这些及模型配置、优化器设置、设备/精度策略绑定到训练合同，并使用严格的可训练权重载入方法。当前组件限定在**无异步数据worker、无梯度累计、每次优化更新完成后**保存；没有宣称多worker预取、AMP或分布式恢复已经验收。

## 验证结果

使用7个固定合成索引、批量3、总共11次合成优化更新的小网络；含冻结线性编码器、可训练头和Dropout，并实际消耗Python/NumPy随机数、Torch噪声与扩散式时间步。不是CLIP、机器人模型或真实数据训练，也不代替训练预算选择。

| 验证环境 | 路径数 | 结果 |
| --- | ---: | --- |
| CPU | 48 | 中断/不中断逐项完全相同 |
| CUDA，本地RTX 4060 Laptop GPU | 48 | 中断/不中断逐项完全相同 |

每组覆盖两种采样方式、恒定与余弦学习率、两个种子，以及短尾批次前后、完整遍历边界和多次中断。核对批次索引、噪声/时间步、随机数、学习率、损失、最终可训练参数、AdamW状态、采样状态与训练随机状态。

拒绝项包括更改总预算、批量、索引顺序、采样方式/权重合同、调度策略或语言条件；这些拒绝发生在模型载入及全局随机状态改变前。还验证：

- 保存断点本身不消耗训练随机序列。
- 临时指标计算若使用保存/恢复保护，不影响后续序列。
- 故意丢弃恢复后的随机状态时，差异被检出，避免“无论恢复是否正确都能通过”的测试。
- 预算耗尽后不能再申请批次；重复申请未提交批次、保存未提交更新均被拒绝。

证据：[CPU报告](../reports/step_training_state_20261020/report.json)、[CUDA报告](../reports/step_training_state_cuda_20261020/report.json)。各自保存当次源码快照与SHA；CPU证据对应原CPU验证脚本，CUDA证据对应后续增加设备选项的脚本。CUDA峰值保留显存记录在报告中。
