# ScalingUp参考与Bridge数据的对应关系

日期：2026-10-09。完成真实数据读取和表示核验，未训练参考策略，未读验证/保留测试载荷，未改正式8维模型。

## 实际读取的样本

从195008固定训练窗口中，选择本地仍保留的10个窗口，覆盖五个任务、160个目标。样本ID、字段、像素载荷统计及来源SHA256保存在 `reports/scalingup_bridge_input_contract_20261009.json`。这些是10个训练演示的首窗口，不代表全训练集统计。

## 已核验的转换

当前标签按 `relative_pose_action` 从世界到达位姿转为输入时刻工具坐标系的相对动作；再用 `decode_relative_pose` 还原。160个目标最大位置误差为1.666e-8米，旋转矩阵分量最大误差1.788e-7。将还原旋转矩阵上两行展平为6D并恢复完整矩阵，最大分量误差同为1.788e-7。

这支持当前相对位姿编码/解码在这些样本中自洽，没有发现明显量纲或四元数顺序错误。它不是独立物理标定或整个dataloader正确性的证明；编码和解码自洽不能验证原始state的坐标定义、同步或控制语义。

## 对照契约

| 数据项 | 作者固定版本的定义 | Bridge可以提供什么 | 当前决定 |
| --- | --- | --- | --- |
| 位置 | 动作ee_pos；本体状态end_effector_position | state的世界xyz；当前标签还原后是未来观测xyz | 到达位姿与控制命令明确分开，不假称相同监督 |
| 旋转动作 | upper_mat为旋转矩阵上两行，按行展平6维 | state的Euler XYZ可转矩阵；相对四元数可还原世界矩阵 | 表示转换已核验；参考动作10维仅供独立对照，正式输出仍8维 |
| 本体状态旋转 | end_effector_orientation；proprio_dim=13对应xyz3、矩阵9、命令1 | 当前/先前state的旋转矩阵 | 可从观测生成，但不使用未来state作为条件 |
| 本体状态夹爪 | gripper_command | state[:,6]为测量；action[:,6]为开合命令 | 测量不冒充命令；episode首时刻先前命令没有证据，不填成真实已知值 |
| 观测历史 | 默认two_proprio | 全轨迹可以取state[t-1]和state[t] | 首时刻只能重复state[0]并记录padding；不存在真实过去状态 |
| 图像 | 论文的工作区/腕部两相机 | 记录中有image_0/1/2/3，但内容不总有效，角色未核实 | 不将两个任意字段宣称为论文两相机；不把黑图当真实第二视角 |
| 预测窗口 | 官方默认16步、按本体状态历史和执行窗口对齐 | 当前标签为state[t+1:t+17] | 不能直接沿用作者当前控制时刻的索引规则；先明确命令与执行后观测的时间关系 |
| 开合极性 | 官方数据是控制ee_gripper_comm | 当前标签为-1关闭、+1打开 | 未核实作者控制bool的物理含义前不做自动极性转换 |
| 归一化 | action_norm_config，训练范围转[-1,1]，推理反变换 | 目前位移固定除0.10m | 未来只从完整训练分区拟合；本10窗口不用于确定正式范围；常量维度需明确处理 |

image_3在所查帧中为全黑。非均匀只是像素统计，不证明相机角色或画面可用于任务。当前正式loader只用image_0；本结果未发现这些输入帧为空，也没有证明增添其它视角会改善模型。

## 目前能做与不能做的结论

可以用这些Bridge观测建立一个明确标注为“作者扩散核心适配Bridge到达位姿”的参考，而不能称为原论文控制策略的完整复现。若下一项只想比较扩散核心，应保持已有8维到达位姿、图像/语言条件、数据分区、损失和预算，不同时换成10维、双相机和新历史条件。否则即使变好也无法判断哪个因素起作用。

若要验证原论文整套成功方案，则应使用作者支持的数据/控制接口，先确认存储和完整配置，不以Bridge的到达位姿冒充控制标签。

本次没有选择并提交上述任一训练分支。完成的是输入契约核验，尚不能宣布根因解决。当前最具体的排除结果是：所查160个目标的相对位姿编码/逆变换没有出现明显数值错误。
