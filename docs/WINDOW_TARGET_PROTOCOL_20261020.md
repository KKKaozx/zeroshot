# 窗口目标与执行协议组件

2026-10-20。新增独立组件`code/window_target_protocol.py`，将此前BC-Z目标核对中的要求落实为可调用校验函数。**尚未修改Dataset、主训练器、检查点或LIBERO执行器的现有行为，也没有生成真实窗口清单。**

## 明确区分的内容

- `observed_future_reached_pose`：目标索引为观测`t+1..t+H`。
- `native_future_setpoint`：目标是同一输入观测下的原生槽，当前支持BC-Z的0..9槽；位姿与夹爪必须来自同槽。
- 统一输出仍为固定输入参考位姿下的8维动作，显式声明工具坐标或源Cartesian表示。增量累加参考不被本版协议接收。
- reached的夹爪策略分为前一观测首槽命令、旧传感器阈值标签、无夹爪。规则与监督mask必须一致；不能给Language Table等部分标签虚构夹爪。
- 单位换算可以明确为未知；时间可为未知、固定时距或每窗口实测时间戳。未知不自动变成1米单位或0.1秒间隔。不同来源只有在固定时距一致时才能声明共享物理时间网格。

协议绑定的是**实际窗口数据身份**，不是只有演示条目的候选清单。当前实际窗口身份尚未形成，组件不会替它填一个看似有效的值。

## 接口

| 函数 | 作用 |
| --- | --- |
| `validate_protocol` | 检查声明结构和内部一致性；返回协议SHA |
| `window_layout` | 从已声明规则生成预期行/槽索引、监督mask和时间布局；不读取原始记录 |
| `validate_window_layout` | 拒绝位姿/夹爪错槽、命令错行、补齐行变监督及时间不匹配 |
| `bind_artifacts` | 返回绑定同一协议的窗口清单和模型配置副本；不原地改文件 |
| `validate_checkpoint_binding` | 核对窗口、检查点所带协议和模型配置摘要一致 |
| `check_prediction_execution_binding` | 检查模型完整预测的运行时协议、坐标、尺度、参考、时间网格、原生控制tick和执行前缀 |

窗口布局只核对索引声明，不证明实际标签张量由这些记录生成；后续真实加载器仍须把原始记录、数值目标和mask逐项绑定。这里也不替代冻结分区、来源去重或数据内容检查。

## 执行兼容与真实资格的区别

执行兼容检查要求：所有来源声明单位依据，目标共用固定时间网格，有夹爪来源声明配对依据，运行时协议摘要完全一致，目标时间落在控制tick上。不从名义控制频率推算未知目标时间，也不做隐式插值。

来源标签与模型预测分别处理：二维/无夹爪来源可参与混源部分监督；其占位标签不能冒充完整模型预测。反过来，存在部分监督来源也不意味着模型从其他来源学得的完整8维预测必然不可用。组件不据此判断模型是否会抓取。

证据引用需包括URI、内容SHA和所支持的声明，但这些字段本身**不是已经独立验证过的物理标定**。因此执行兼容结果明确返回`physical_qualification_proven=false`及`learned_success_proven=false`。合成证据不得作为真实来源的依据。

## 已做验收

仅运行标准库合成检查，无Torch/TensorFlow导入、模型、仿真或真实记录解码。6项正向场景通过：观测目标、同槽原生目标、短尾掩码、逐窗口不规则时间、清单至运行时绑定，以及混源部分监督。

43项拒绝检查覆盖：原生槽伪装观测行、跨槽夹爪、前一命令错行、伪造补齐标签、未知时间被强填、来源时间网格冲突、单位/配对依据缺失、运行时尺度/参考/帧/时间表变更、非整数控制tick、检查点摘要/数据身份不一致等。可变证据与协议内容改变后不能继续沿用旧摘要。
