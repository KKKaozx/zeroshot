# Adapter冻结与联合训练的严格对照

日期：2026-10-04。本实验只回答：当前权重继续训练时，Adapter参与优化是否会阻止训练样本拟合。不是从头训练消融，不是机器人任务成功率实验。

## 统一条件

- 初始化：`results/bridge_single_task_full_validation_v1/latest.pt`；两组初始参数逐位相同。
- 数据：固定训练316窗口（17演示）、验证55窗口（3演示），每次评估均覆盖全部窗口；测试目标不参与。
- CLIP冻结；原架构、动作头、标签、损失、当前夹爪输入不变。
- 两组均为1500次更新、batch=64、AdamW、统一学习率3e-4、weight decay=0、seed=42。
- 每250次更新及更新前评估训练和验证。完整随机批次序列只生成一次并由两组共用，保存于`batch_schedule.pt`。
- 两组唯一实验因素：Adapter参数是否参与优化。没有按分支调参或提前停止。
- 缓存冻结CLIP特征。当前Adapter只读CLS，层内没有视觉token之间的混合，因此可只计算CLS查询；先验证与完整257视觉token的输出、Adapter梯度等价。最大输出数值差4.0e-6、最大梯度数值差9.9e-5；两组使用相同缓存计算路径。

## 结论

1. 两组都可以显著改善完整训练集拟合。联合训练没有让模型完全无法学习；不能把之前失败简单归因于Adapter参与训练。
2. 在相同预算下，冻结组的训练位置拟合更好，切换也更完整。这是本次单种子、当前权重继续训练的结果，不是冻结Adapter普遍更好的证明。
3. 联合组验证旋转误差有所降低，但17.55°仍差于12.94°的保持姿态基线；验证位置仍差于不动基线。两组关闭→打开都为0/6。
4. 训练拟合与新演示泛化必须分别处理。剩余重点是输入表示、场景/轨迹差异和泛化，而不是再检查动作头是否具备拟合能力。
5. 本轮不能验收语言泛化、扩散解码器或闭环控制。所有样本属于同一个语言任务，没有因此证明论文中的跨任务零样本能力。

## 验证与限制

原始权重SHA-256保持一致。冻结组Adapter未变化，联合组Adapter已更新；CLIP权重在训练过程完成哈希核验。初始训练指标一致，验证初始指标差在约1e-7数量级，属于浮点计算容差；初始权重逐位相同。先前结束校验使用整份浮点字典完全相等，过于严格；已核验保存的完成权重并修正容差，没有重复训练。

学习率、batch和继续训练预算不同于更早的25轮原实验。本次严格比较只隔离Adapter训练状态，不能分别回答原实验的学习率或总更新次数贡献。

## 文件

- `comparison.json`：两组所有评估点、完整配置、覆盖索引、参数和文件校验。
- `history.csv`：各评估点训练/验证指标，可用于绘图。
- `adapter_frozen_step_*.pt` / `adapter_joint_step_*.pt`：各评估点诊断权重，未覆盖原模型。
- `batch_schedule.pt`：两组共用的训练窗口序列。

## 复现

已完成，无需为继续工作重复运行。需要复现时，在项目根目录使用现有`zeroshot-gpu`环境并指定新输出目录：

```powershell
python code/compare_bridge_adapter_training.py --output-dir results/bridge_adapter_trainability_reproduction
```

先不进入仿真或混入其他数据集。下一步应围绕现有输入能否区分新演示的动作阶段展开诊断，先查看视觉特征相近窗口的动作差异与场景差异，再选择一个受控改动；不能根据本轮结果直接宣布要换主干或加数据。
